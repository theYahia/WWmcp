## 1. Что это и кому нужно

Сервер даёт ИИ-агенту доступ к API hh.ru: вакансии, работодатели, резюме, справочники
регионов, профессиональных ролей и отраслей, подсказки-автодополнения и расчётная
зарплатная статистика. Круг задач — всё, что обычно делается руками в поиске hh.ru, но
требует перебора десятков карточек: собрать выборку вакансий по нескольким фильтрам,
сравнить зарплаты по регионам, посмотреть, что открыто у конкретной компании, подобрать
похожие вакансии к найденной. Для работодателя с платным доступом добавляется поиск по базе
резюме.

Ответы по умолчанию приходят **сжатой сводкой**, а не сырым JSON: карточки hh.ru глубоко
вложены и в исходном виде занимают на порядок больше места, чем полезная информация. Любой
поисковый инструмент и инструмент карточки принимает `raw: true` — тогда возвращается
полный JSON hh.ru.

Сервер работает только на чтение: откликнуться на вакансию, опубликовать вакансию или
изменить резюме через него нельзя.

## 2. Установка и подключение

Токен для большинства инструментов не нужен — сервер запускается и работает без него.

### Claude Desktop

Файл `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "hh": {
      "command": "npx",
      "args": ["-y", "@theyahia/hh-mcp"],
      "env": { "HH_ACCESS_TOKEN": "необязательный-oauth-токен" }
    }
  }
}
```

Без токена блок `env` можно опустить целиком. Клиент читает конфигурацию при старте — после
правки его нужно перезапустить.

### Claude Code

```bash
claude mcp add hh -- npx -y @theyahia/hh-mcp
# с токеном:
claude mcp add hh -e HH_ACCESS_TOKEN=ваш-токен -- npx -y @theyahia/hh-mcp
```

### Cursor / Windsurf / VS Code (Copilot)

Cursor и Windsurf принимают тот же блок `mcpServers` в своих настройках MCP. У VS Code
конфигурация лежит в `.vscode/mcp.json`, и корневой ключ там — `servers`, а не `mcpServers`;
поля `command`, `args` и `env` те же.

### Режим Streamable HTTP

```bash
npx @theyahia/hh-mcp --http
# либо: HTTP_PORT=8080 npx @theyahia/hh-mcp
```

Эндпоинты: `POST /mcp` — запросы MCP в режиме **stateless** (сервер и транспорт создаются на
каждый запрос и уничтожаются по закрытии ответа); любой другой метод на `/mcp` даёт `405` с
заголовком `Allow: POST`; `GET /health` возвращает `{"status":"ok","tools":19,"version":"…"}`;
прочие пути — `404` с подсказкой.

Порт берётся из `HTTP_PORT`, затем `PORT`, иначе 3000. Сервер слушает `127.0.0.1`, если не
задан `HOST`. Включена защита от DNS rebinding: принимаются только запросы, у которых
заголовок `Host` есть в списке разрешённых — по умолчанию `127.0.0.1:<порт>` и
`localhost:<порт>`. Чтобы открыть доступ извне, нужно одновременно задать `HOST=0.0.0.0` и
перечислить свои адреса в `HH_ALLOWED_HOSTS` (и при необходимости источники в
`HH_ALLOWED_ORIGINS`), после чего закрыть порт собственной аутентификацией: у `/mcp` её нет.
Тело запроса больше 4 МБ отклоняется.

### Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `HH_ACCESS_TOKEN` | нет | OAuth-токен. Нужен только для резюме (см. раздел 3) |
| `HH_USER_AGENT` | нет | Значение заголовка `HH-User-Agent`. По умолчанию `hh-mcp/<версия> (+https://github.com/theYahia/hh-mcp)` |
| `HTTP_PORT` / `PORT` | нет | Порт режима HTTP (по умолчанию 3000) |
| `HOST` | нет | Интерфейс для режима HTTP (по умолчанию `127.0.0.1`) |
| `HH_ALLOWED_HOSTS` | нет | Список разрешённых значений `Host` через запятую |
| `HH_ALLOWED_ORIGINS` | нет | Список разрешённых источников через запятую |
| `MCP_DISABLE_SANITIZE` | нет | `true` отключает фильтрацию ответов от инъекций |

`HH_USER_AGENT` стоит задать своим значением с контактным адресом (например,
`my-app/1.0 (me@example.com)`): hh.ru требует этот заголовок и по нему связывается с
владельцем интеграции.

## 3. Где взять токен и зачем он нужен

Сервер работает в двух режимах.

| Режим | Что доступно |
|---|---|
| **Без токена** | Поиск вакансий, карточка вакансии, похожие вакансии, работодатели и их вакансии, зарплатная статистика, все справочники и подсказки, проверка токена |
| **С токеном** | Всё перечисленное плюс поиск резюме и карточка резюме |

Токен выпускается в кабинете разработчика hh.ru: `https://dev.hh.ru/admin`. Этот адрес
сервер называет сам в ответе `validate_token`, когда токен истёк.

Ключевая оговорка по резюме: одного токена мало. Нужны **работодательский** аккаунт и
**платная подписка на базу резюме**. Токен соискателя или анонимный доступ к резюме приводит
к отказу `403`. Проверить, что именно даёт ваш токен, можно инструментом `validate_token`:
он обращается к `/me` и возвращает роли учётной записи (`employer`, `applicant`, `admin`).

Если токен не задан вовсе, `search_resumes` и `get_resume` завершатся ошибкой ещё до
обращения к API — сервер проверяет наличие переменной сам.

## 4. Инструменты по задачам

Почти все инструменты принимают `raw` (логический). Без него возвращается компактная сводка:
HTML-разметка из описаний вырезана, длинные тексты усечены. С `raw: true` — полный JSON
ответа hh.ru.

### 4.1 Искать вакансии

**`search_vacancies`** — основной инструмент. Обязательных параметров нет, но пустой поиск
бессмысленен. Параметры:

| Параметр | Тип, значения | Комментарий |
|---|---|---|
| `text` | строка | Поддерживает язык запросов hh.ru: кавычки, `AND` / `OR` / `NOT`, префиксы полей |
| `area` | число | Код региона (1 — Москва, 2 — Санкт-Петербург). Ищется через `get_areas` или `suggest_areas` |
| `professional_role` | число | Код профессиональной роли, из `get_professional_roles` |
| `industry` | строка | Код отрасли работодателя, из `get_industries` |
| `metro` | строка | Код станции или ветки метро, из `get_metro` |
| `employer_id` | строка | Ограничить одним работодателем |
| `salary` | число | Желаемая зарплата |
| `currency` | строка | `RUR`, `USD`, `EUR`. Отправляется **только вместе с** `salary`; по умолчанию `RUR` |
| `label` | `with_salary`, `not_from_agency`, `accept_handicapped`, `accept_kids`, `accept_temporary` | Заменяет устаревший `only_with_salary` |
| `experience` | `noExperience`, `between1And3`, `between3And6`, `moreThan6` | Требуемый опыт |
| `employment_form` | `FULL`, `PART`, `PROJECT`, `FLY_IN_FLY_OUT` | Современная замена `employment` |
| `work_format` | `ON_SITE`, `REMOTE`, `HYBRID`, `FIELD_WORK` | Современная замена `schedule` |
| `employment` | `full`, `part`, `project`, `volunteer`, `probation` | **Устарел** у hh.ru, но принимается |
| `schedule` | `fullDay`, `shift`, `flexible`, `remote`, `flyInFlyOut` | **Устарел** у hh.ru, но принимается |
| `search_field` | `name`, `company_name`, `description` | Искать только в одном поле |
| `excluded_text` | строка | Исключить вакансии с этим текстом |
| `period` | 1–30 | Опубликованные за последние N дней |
| `date_from`, `date_to` | ISO 8601 | Границы периода публикации |
| `order_by` | `relevance`, `publication_time`, `salary_desc`, `salary_asc` | Сортировка |
| `per_page` | 1–100, по умолчанию 20 | Записей на странице |
| `page` | с 0, по умолчанию 0 | Номер страницы |

Два правила проверяются сервером до обращения к API: `period` несовместим с
`date_from`/`date_to`, а произведение `(page + 1) × per_page` не должно превышать 2000 —
это предел глубины пагинации у hh.ru.

**`get_vacancy`** — карточка вакансии целиком: описание, требования, ключевые навыки,
контакты, работодатель. Обязателен `vacancy_id` — числовой идентификатор.

**`get_similar_vacancies`** — похожие вакансии. Обязателен `vacancy_id`; `per_page` (1–100,
по умолчанию 20) и `page` необязательны.

### 4.2 Изучать работодателей

**`search_employers`** — поиск компаний. Обязателен `text` (название). Необязательны `area`,
`per_page`, `page`.

**`get_employer`** — профиль компании: описание, отрасли, сайт, число вакансий. Обязателен
`employer_id` (числовой).

**`get_employer_vacancies`** — активные вакансии компании. Обязателен `employer_id`;
`per_page` и `page` необязательны.

### 4.3 Находить коды для фильтров

Фильтры поиска принимают коды, а не названия. Эта группа их и выдаёт.

**`get_areas`** — всё дерево регионов и городов строками `id — название`. Ответ большой;
если нужна одна страна, берите следующий инструмент.

**`get_areas_subtree`** — поддерево одного узла. Обязателен `area_id` (числовая строка,
например `113` — Россия, `1` — Москва).

**`get_professional_roles`** — дерево профессиональных ролей с кодами по категориям.

**`get_industries`** — дерево отраслей компаний с кодами.

**`get_metro`** — станции и ветки метро. Необязательный `city_id` (числовая строка) сужает
до одного города; без него возвращается метро всех городов.

**`get_dictionaries`** — все справочники сразу: валюты, типы занятости, графики, уровни
опыта, метки вакансий и прочее. Параметров нет.

**`suggest_positions`**, **`suggest_companies`**, **`suggest_areas`** — автодополнение по
должностям, компаниям и городам. У каждого обязателен `text` — начало названия. Возвращают
строки вида `Название (id=…)`. Быстрее, чем выкачивать целое дерево, когда нужно опознать
одно значение.

### 4.4 Оценивать зарплаты

**`get_salary_statistics`** — распределение зарплат по роли и региону. Обязателен
`professional_role_id`; необязательны `area_id`, `text` (уточняющее слово, например
`senior python`), `sample_pages` (1–5, по умолчанию 2) и `raw`.

Как считается. Сначала один запрос за общим числом вакансий по фильтру — он нужен для
показателя покрытия. Затем до `sample_pages` страниц по 100 вакансий с меткой
`with_salary`. Для каждой вакансии берётся середина вилки (если указана одна граница — она
сама). Значения группируются по валютам, для расчёта берётся самая многочисленная, остальные
только пересчитываются штуками. Результат: медиана, P25, P75, минимум, максимум, среднее,
размер выборки и доля вакансий с указанной зарплатой.

Это **оценка по объявлениям, а не статистика рынка**, и сервер прямо пишет об этом в ответе:
учитываются только вакансии, где зарплата раскрыта; суммы «до вычета налога» и «на руки»
смешаны; глубина выборки ограничена. Официальные данные даёт платный сервис hh.ru «Банк
данных зарплат»; бесплатного эндпоинта распределения зарплат у hh.ru нет.

### 4.5 Резюме и диагностика доступа

**`validate_token`** — проверка `HH_ACCESS_TOKEN` через `/me`. Возвращает имя, почту и роли
учётной записи, а также прямо сообщает, доступен ли поиск резюме. Если токен не задан —
говорит об этом без обращения к API. Первый инструмент, который стоит вызвать при отказах
доступа.

**`search_resumes`** — поиск резюме. Необязательные `text`, `area`, `professional_role`,
`salary`, `experience` (те же значения, что у вакансий), `per_page`, `page`. Требует
токена работодателя и платной подписки.

**`get_resume`** — резюме целиком: опыт, образование, навыки, контакты. Обязателен
`resume_id` (буквенно-цифровой идентификатор, не числовой). Те же требования к доступу.

## 5. Готовые сценарии

**1. «Найди удалённые вакансии Python-разработчика в Москве от 300 000 ₽.»**
`suggest_areas` (`text: "Москва"`) → `search_vacancies` (`text: "python"`, `area: 1`,
`work_format: "REMOTE"`, `salary: 300000`, `label: "with_salary"`). Метка `with_salary`
здесь существенна: без неё в выдачу попадут вакансии без указанной зарплаты, и фильтр по
сумме отработает не так, как ожидается.

**2. «Что открыто в Яндексе прямо сейчас?»**
`suggest_companies` (`text: "Яндекс"`) → `get_employer_vacancies` (`employer_id`,
`per_page: 100`). Инструмент возвращает только активные вакансии.

**3. «Сравни зарплаты бэкенд-разработчиков в Москве и Петербурге.»**
`get_professional_roles` (найти код роли) → `get_salary_statistics` (`professional_role_id`,
`area_id: 1`, `sample_pages: 5`) → тот же вызов с `area_id: 2`. Сравнивать нужно медианы и
пары P25–P75, а не средние: выборка смещённая.

**4. «Собери все вакансии аналитика за последнюю неделю.»**
`search_vacancies` (`professional_role`, `period: 7`, `per_page: 100`, `page: 0`) →
`page: 1`, ... до исчерпания. Дальше 20 страниц по 100 не уйти — предел глубины 2000
результатов; чтобы получить больше, период дробится на отрезки через `date_from` / `date_to`.

**5. «Разбери эту вакансию и найди похожие.»**
`get_vacancy` (`vacancy_id`) → `get_similar_vacancies` (тот же `vacancy_id`). Для чтения
описания достаточно сводки; `raw: true` нужен, только если требуются служебные поля hh.ru.

**6. «Найди вакансии в ИТ-компаниях у метро Технопарк.»**
`get_industries` (код отрасли) → `get_metro` (`city_id: "1"`, найти код станции) →
`search_vacancies` (`industry`, `metro`, `area: 1`).

**7. «Мой токен вообще позволяет искать резюме?»**
`validate_token`. Если в ролях нет `employer` — поиск резюме недоступен независимо от того,
насколько свежий токен.

**8. «Найди кандидатов с опытом 3–6 лет на роль тестировщика.»**
`validate_token` (убедиться в правах) → `get_professional_roles` →
`search_resumes` (`professional_role`, `experience: "between3And6"`, `area`) →
`get_resume` по интересным идентификаторам.

## 6. Ограничения и подводные камни

### 6.1 Предел глубины пагинации — 2000 результатов

hh.ru не отдаёт больше 2000 записей на один набор фильтров. Сервер проверяет это до запроса:
если `(page + 1) × per_page` превышает 2000, вызов завершается ошибкой с подсказкой сузить
фильтры или разбить период. Тот же предел действует внутри `get_salary_statistics` — отсюда
верхняя граница `sample_pages` в 5 страниц по 100 вакансий.

Обход один: разбивать выборку датами (`date_from` / `date_to`) или другими фильтрами и
объединять результаты.

### 6.2 Ограничение частоты — 5 запросов в секунду

Ограничитель встроен в клиента: он держит отметки времени последних запросов и, если в
последнюю секунду их уже пять, ждёт освобождения окна. Счётчик один на процесс — в режиме
HTTP его делят все подключённые клиенты, то есть общий бюджет не растёт с числом
пользователей.

При ответе `429` сервер читает заголовок `Retry-After` (секунды) и ждёт указанное время;
без заголовка — экспоненциальная задержка `1000 × 2^(попытка−1)` мс, но не больше 8 секунд.
Попыток не больше трёх, после чего возвращается ошибка «все попытки исчерпаны».

Учтите, что `get_salary_statistics` — это от двух до шести запросов за один вызов: серия
таких вызовов подряд выбирает лимит быстрее, чем кажется.

### 6.3 Отказы доступа не повторяются

`401` и `403` возвращаются немедленно, без повторов: перебирать заведомо отвергнутый токен
бессмысленно. Ответы `5xx` и таймауты повторяются (до трёх попыток; таймаут одного запроса —
10 секунд, повтор по нему идёт без паузы).

### 6.4 Заголовок `HH-User-Agent` обязателен

hh.ru требует его в каждом запросе. Сервер подставляет значение по умолчанию с адресом
репозитория как контактом и дублирует его в стандартный `User-Agent` — для прокси и CDN,
которые смотрят именно туда. Для своей интеграции значение следует переопределить
переменной `HH_USER_AGENT`, указав приложение и контактную почту: запросы с чужим или
безымянным агентом рискуют попасть под блокировку или капчу.

### 6.5 Устаревшие фильтры

Параметры `employment` и `schedule` помечены hh.ru как устаревшие, но сервер их принимает и
передаёт как есть. В новых сценариях используйте `employment_form` и `work_format`; смешивать
пары не нужно. Аналогично `only_with_salary` заменён меткой `label: "with_salary"` —
отдельного параметра под старым именем в схеме нет.

### 6.6 Формат идентификаторов проверяется

`vacancy_id`, `employer_id`, `area_id` и `city_id` обязаны быть числовыми строками,
`resume_id` — строкой из букв, цифр, дефиса и подчёркивания. Проверка выполняется схемой до
запроса; она же не даёт подставить в путь URL произвольный текст. Ошибка «должен быть
числовым id» означает, что в аргумент попало название вместо кода.

### 6.7 Объём ответа и фильтрация

Ответ длиннее 50 000 символов обрезается с пометкой о срезке — с `raw: true` на выдаче в 100
вакансий это происходит легко. Тексты вакансий и резюме пишут работодатели и соискатели,
поэтому все ответы проходят фильтр: конструкции вида «игнорируй предыдущие инструкции»,
«ты теперь…» и теги `<system>` заменяются на `[filtered]`. Отключается переменной
`MCP_DISABLE_SANITIZE=true`; для этого сервера отключать не следует — тексты здесь
пользовательские по определению.

### 6.8 Зарплатная статистика — оценка, а не факт

Смещение выборки заложено в источник данных: вакансии без зарплаты в расчёт не попадают, а
раскрывают её не все и не в каждом сегменте одинаково. Дополнительно смешиваются суммы до
налога и на руки. Пользоваться этими числами как ориентиром можно, ссылаться на них как на
рыночную статистику — нет.

## 7. Частые ошибки

Ошибки возвращаются модели как результат с признаком `isError: true`. Сообщение состоит из
типовой фразы категории и хвоста `Детали: <текст от hh.ru>`.

| Что видно | Что это значит | Что делать |
|---|---|---|
| `HH_ACCESS_TOKEN is not set…` | Вызван `search_resumes` или `get_resume` без токена | Задать токен в блоке `env` конфигурации клиента; проверить `validate_token` |
| `Unauthorized — set HH_ACCESS_TOKEN…` (401) | Токен отсутствует, недействителен или истёк | Выпустить новый на `https://dev.hh.ru/admin` |
| `Forbidden — token lacks required scope…` (403) | Токен есть, но прав на эндпоинт нет. Для резюме — обычно нет роли работодателя или платной подписки | `validate_token` покажет роли; подписка проверяется в кабинете hh.ru |
| `Токен задан, но недействителен или истёк (HTTP 401/403)` в ответе `validate_token` | Диагностика подтвердила: дело в токене | Заменить токен |
| `period is mutually exclusive with date_from/date_to` | Заданы и `period`, и границы дат | Оставить что-то одно |
| `hh.ru caps pagination depth at 2000 results…` | Запрошена страница за пределом глубины | Сузить фильтры или разбить период (раздел 6.1) |
| `Rate limited — all retries exhausted` (429) | Лимит частоты выбран, три попытки не помогли | Пауза; в режиме HTTP уменьшить число одновременных клиентов |
| `Ошибка сервера (HTTP 5xx)` | hh.ru временно недоступен | Повторить через 10–30 секунд; три попытки уже были |
| `Таймаут запроса` | Ответ не пришёл за 10 секунд | Уменьшить `per_page`, повторить |
| `vacancy_id must be a numeric hh.ru id` (и аналоги) | В идентификатор попало название или ссылка | Взять код из результатов поиска или из подсказок `suggest_*` |
| `Нет вакансий с указанной зарплатой для professional_role=…` | Выборка `get_salary_statistics` пуста | Убрать `text`, расширить регион, проверить код роли |
| `Ресурс не найден` (404) | Вакансия снята, работодатель удалён или код неверен | Проверить идентификатор поиском |
| `(нет совпадений)` от `suggest_*` | Подсказок по строке нет | Сократить строку до первых нескольких букв |
| Ответ обрывается фразой о срезке | Ответ длиннее 50 000 символов | Убрать `raw: true`, уменьшить `per_page` |

Весь журнал сервера идёт в **stderr** — stdout занят протоколом JSON-RPC. При старте в
stdio-режиме сервер пишет число инструментов и указывает, задан ли токен.

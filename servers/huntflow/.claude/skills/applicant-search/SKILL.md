# /applicant-search — Найти кандидата

## Алгоритм

1. `list_accounts` — доступные аккаунты HuntFlow. Все остальные инструменты требуют account_id, поэтому это первый шаг, если ID не задан.
2. `search_applicants` (account_id, q — имя, email или телефон, vacancy, status, tag, count, page) — поиск. Фильтры vacancy, status и tag принимают **числовые ID**, а не названия.
3. Расшифруй справочники, чтобы фильтры и вывод были читаемыми:
   - `list_stages` (account_id) — этапы подбора, сопоставление status → название;
   - `list_tags` (account_id) — теги аккаунта;
   - `list_sources` (account_id) — откуда пришёл кандидат.
4. Открой карточку: `get_applicant` (account_id, applicant_id) — полная информация.
5. Резюме: `get_applicant_resumes` (account_id, applicant_id) — список прикреплённых, из него возьми external_id. Тело конкретного резюме — `get_resume` (account_id, applicant_id, external_id).
6. Сопоставь опыт кандидата с требованиями и покажи вывод, а не пересказ резюме целиком.

## Важно

- Инструменты этого сервера только читают: сменить этап, оставить комментарий или отказать через MCP нельзя — это делается в интерфейсе HuntFlow.
- Выдача постраничная (count, page). Прежде чем говорить «всего N кандидатов», убедись, что прошёл все страницы, иначе укажи, сколько просмотрел.
- Контакты кандидатов — персональные данные: выгружай их точечно, а не пачкой в чат.

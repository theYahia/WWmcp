# /receipts-report — Чеки Payme за период

## Алгоритм

1. Преобразуй даты пользователя в **миллисекундные** timestamp: from — начало периода,
   to — конец. Payme принимает миллисекунды, не секунды; ошибка в 1000 раз даёт пустой ответ.
2. Вызови `receipts_get_all` с from, to, offset (по умолчанию 0) и limit
   (по умолчанию 50, увеличивай для больших периодов).
3. Листай через offset, пока страница не станет короче limit. Не называй итоговое число,
   если не дошёл до конца выборки.
4. Сгруппируй чеки по статусу, суммы переведи из тийинов в сумы (раздели на 100).
5. Отдельно выдели чеки, которые созданы, но не оплачены дольше суток — это брошенные
   корзины. По каждому спорному вызови `receipts_check` с его id для свежего состояния.
6. Если пользователь просит закрыть зависшие — по каждому вызови `receipts_cancel`
   с id и числовым reason, подтвердив список перед первым вызовом.

## Формат ответа

```
## Чеки Payme — 01.09.2026 — 03.09.2026

| Статус | Количество | Сумма |
|--------|-----------|-------|
| оплачен | 84 | 12 400 000 сум |
| ожидает | 11 | 1 620 000 сум |
| отменён | 3 | 450 000 сум |

**Оборот**: 12 400 000 сум

### Зависшие дольше суток
- id 5f8a... — 150 000 сум — создан 01.09
```

## Важно

- from и to — **миллисекунды** (Date.now()), не секунды Unix.
- Суммы в ответе API — тийины. Делить на 100 перед показом.
- Сервер по умолчанию работает в песочнице; отчёт из песочницы не равен боевым оборотам.
  Скажи, из какого контура данные.

## Примеры

```
/receipts-report 2026-09-01 2026-09-03
/receipts-report за вчера
```

# Руководство пользователя tkassa-mcp

Пакет `@theyahia/tkassa-mcp`, версия 2.0.1, 16 инструментов. Node.js 18 и выше.
API T-Kassa (Т-Банк), точка входа `https://securepay.tinkoff.ru/v2`; два инструмента
работают с отдельным API Т-Инвестиций.

## 1. Что это и кому нужно

Сервер даёт ИИ-агенту доступ к платёжному контуру T-Kassa: выставить счёт и получить
ссылку на оплату, подтвердить или отменить двухстадийный платёж, вернуть деньги, вести
покупателей и их привязанные карты, списывать по подписке, создавать QR-код СБП,
отправлять закрывающий чек по 54-ФЗ. Дополнительно — два инструмента к API Т-Инвестиций:
портфель и поиск инструмента.

Задача, которую это снимает: «выстави счёт на 3 500 за подписку», «оплатил ли клиент
заказ 4417», «верни половину», «какие карты покупателя сохранены и с какой можно
списать».

> ⚠️ **Сервер двигает настоящие деньги.** `init_payment`, `confirm_payment`,
> `cancel_payment`, `refund_payment` и `charge_payment` необратимы, а часть из них
> **не защищена ключом идемпотентности** — подробности в разделе 6.2. Пока настраиваете
> интеграцию, работайте на тестовом терминале.

## 2. Установка и подключение

### Claude Desktop

Файл `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "tkassa": {
      "command": "npx",
      "args": ["-y", "@theyahia/tkassa-mcp"],
      "env": {
        "TKASSA_TERMINAL_KEY": "ваш_terminal_key",
        "TKASSA_PASSWORD": "пароль_терминала"
      }
    }
  }
}
```

Клиент читает конфигурацию при старте — после правки его нужно перезапустить.

### Claude Code

```
claude mcp add tkassa -e TKASSA_TERMINAL_KEY=ваш_ключ -e TKASSA_PASSWORD=пароль -- npx -y @theyahia/tkassa-mcp
```

### Cursor / Windsurf / VS Code (Copilot)

Cursor и Windsurf принимают тот же блок `mcpServers` в `.cursor/mcp.json` или
`.windsurf/mcp.json`. У VS Code файл `.vscode/mcp.json`, и корневой ключ там — `servers`,
а не `mcpServers`. Файл рабочей области обычно попадает в систему контроля версий —
`TKASSA_PASSWORD` в нём хранить нельзя: этим паролем подписываются денежные операции.

### Режим Streamable HTTP

```bash
HTTP_PORT=3000 npx @theyahia/tkassa-mcp --http
```

Режим включается флагом `--http` либо самой переменной `HTTP_PORT` (по умолчанию 3000).
Эндпоинты: `POST /mcp` (запросы; инициализация создаёт сессию), `GET /mcp` (поток SSE
существующей сессии), `DELETE /mcp` (завершение сессии), `GET /health` (`status`,
`server`, `version`, `uptime`, `memory_mb`, `tools`). Сессии различаются заголовком
`mcp-session-id`; кросс-доменные браузерные вызовы по умолчанию запрещены.

Ключи берутся из окружения процесса и одни на все сессии. Собственной аутентификации у
`/mcp` нет, а доступ к порту равносилен возможности списывать и возвращать деньги —
публиковать его в недоверенной сети нельзя.

### Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `TKASSA_TERMINAL_KEY` | да | Ключ терминала; уходит в теле каждого запроса полем `TerminalKey` |
| `TKASSA_PASSWORD` | да | Пароль терминала. **Не передаётся по сети**: используется для вычисления подписи SHA-256 |
| `TINKOFF_INVEST_TOKEN` | нет | Токен API Т-Инвестиций; нужен только для `get_invest_portfolio` и `find_instrument` |
| `HTTP_PORT` | нет | Порт HTTP-режима; заданная переменная сама включает режим |
| `MCP_DISABLE_SANITIZE` | нет | `true` отключает фильтрацию ответов от инъекций |

Отсутствие платёжных ключей обнаруживается **при первом вызове платёжного инструмента**,
а не при старте: клиент создаётся лениво. Отсутствие токена Т-Инвестиций не мешает
работать со всем остальным — он проверяется только в момент вызова своих двух
инструментов.

## 3. Где взять ключи доступа

**T-Kassa.** Ключ и пароль терминала выдаются в личном кабинете:
**Магазины → Терминалы** (этот путь сервер называет сам в сообщении об отсутствующих
переменных). Кабинет — `https://www.tbank.ru/kassa/`; там же выдаются тестовые реквизиты.

Подпись запроса вычисляется на стороне сервера: значения полей запроса плюс пароль
сортируются по именам ключей, склеиваются и хешируются SHA-256; результат уходит полем
`Token`. Из подписи исключаются вложенные объекты (например, `Receipt`) — так требует
сама T-Kassa. Пароль в сеть не уходит ни в каком виде, но любой, кто получил доступ к
переменной окружения, сможет подписывать операции от вашего терминала.

**Т-Инвестиции.** Токен создаётся в приложении Т-Инвестиций:
**Настройки → Токен для OpenAPI**. Подойдёт токен «только чтение» — оба инструмента
сервера ничего не изменяют. Это **отдельный продукт с отдельным токеном**: ключ терминала
T-Kassa для него не годится и наоборот.

Идентификатор брокерского счёта (`account_id` для портфеля) берётся в профиле
Т-Инвестиций; инструмента получения списка счетов в сервере нет.

## 4. Инструменты по задачам

Все суммы принимаются **в рублях** и переводятся в копейки на стороне сервера
(`100.50` → `10050`). Передавать копейки самостоятельно не нужно и вредно: сумма
увеличится в сто раз.

Ответы возвращаются форматированным JSON — как их отдала T-Kassa, без переупаковки.

### 4.1 Приём платежа

**`init_payment`** — создание платежа. Обязательны `amount` (рубли) и `order_id`
(уникальный номер заказа в вашей системе). Необязательные:

| Параметр | Назначение |
|---|---|
| `description` | Описание, до 250 символов |
| `customer_key` | Идентификатор покупателя в вашей системе — нужен для привязки карт |
| `recurrent` | Значение `Y` — платёж пригоден для последующих списаний по подписке |
| `language` | `ru` (по умолчанию) или `en` — язык платёжной формы |
| `notification_url` | Адрес для уведомлений о смене статуса |
| `success_url`, `fail_url` | Адреса возврата после успешной и неуспешной оплаты |

В ответе приходят `PaymentId` и `PaymentURL` — ссылка, которую отправляют плательщику.

**`get_payment_state`** — текущее состояние по `payment_id`: статус, сумма, `OrderId`,
детали ошибки. Основной инструмент проверки после любой неопределённости.

**`confirm_payment`** — подтверждение двухстадийного платежа: списание удержанных
средств. Обязателен `payment_id`, необязательный `amount` подтверждает часть суммы.

**`cancel_payment`** — отмена платежа. Обязателен `payment_id`, необязательный `amount`
отменяет часть.

**`refund_payment`** — возврат после списания. Обязателен `payment_id`, необязательный
`amount`; без него возврат полный.

> `cancel_payment` и `refund_payment` **обращаются к одному и тому же методу T-Kassa**
> (`/Cancel`) с одинаковым телом запроса. Разделены они по смыслу вызова, а не по
> поведению: у T-Kassa отмена до подтверждения и возврат после — это один метод, а что
> именно произойдёт, определяет текущий статус платежа. Практически: перед вызовом
> посмотрите статус через `get_payment_state`.

### 4.2 Подписки и привязанные карты

**`add_customer`** — регистрация покупателя. Обязателен `customer_key` (ваш
идентификатор), необязательны `email` и `phone`.

**`get_customer`** — сведения о покупателе по `customer_key`.

**`remove_customer`** — удаление покупателя **вместе со всеми его привязанными картами**.

**`get_card_list`** — привязанные карты покупателя: `CardId`, маскированные номера и
`RebillId` для списаний.

**`remove_card`** — удаление карты: обязательны `customer_key` и числовой `card_id` из
`get_card_list`.

**`charge_payment`** — списание по подписке. Обязательны `payment_id` исходного платежа,
созданного с `recurrent: "Y"`, и `rebill_id` карты (из уведомления или `get_card_list`).
Необязательный `amount` — по умолчанию берётся сумма исходного платежа. Списание
проходит **без участия плательщика**.

### 4.3 СБП

**`create_sbp_qr`** — QR-код Системы быстрых платежей по уже созданному `payment_id`.
Параметр `data_type`: `PAYLOAD` (по умолчанию — ссылка для оплаты) или `IMAGE`
(изображение PNG в base64). Платёж должен быть создан заранее через `init_payment`.

**`get_sbp_qr_state`** — статус оплаты по QR: обязателен `payment_id`. Предназначен для
периодического опроса после выдачи кода.

### 4.4 Чеки по 54-ФЗ

**`send_closing_receipt`** — закрывающий чек в ФНС, отправляется при фактической отгрузке
товара после оплаты. Обязательны `payment_id`, `taxation` и непустой массив `items`.

`taxation` — система налогообложения: `osn`, `usn_income`, `usn_income_outcome`, `envd`,
`esn`, `patent`.

У позиции обязательны `Name` (до 128 символов), `Price` (за единицу, в рублях),
`Quantity`, `Amount` (сумма позиции в рублях) и `Tax`:

| `Tax` | Ставка |
|---|---|
| `none` | Без НДС |
| `vat0` | 0 % |
| `vat10` | 10 % |
| `vat20` | 20 % |
| `vat110` | Расчётная 10/110 |
| `vat120` | Расчётная 20/120 |

Необязательные `PaymentMethod` (`full_prepayment`, `prepayment`, `advance`,
`full_payment`, `partial_payment`, `credit`, `credit_payment`) и `PaymentObject`
(`commodity`, `service`, `job`, `payment`, `composite`, `another` и другие). Контакт для
отправки чека — `email` либо `phone`.

Обратите внимание: имена полей позиции здесь **с заглавной буквы** (`Name`, `Price`,
`Tax`), в отличие от остальных инструментов сервера — они передаются в T-Kassa как есть.
Рублёвые `Price` и `Amount` переводятся в копейки автоматически.

### 4.5 Т-Инвестиции

**`get_invest_portfolio`** — портфель: акции, облигации, фонды, их стоимость и результат.
Обязателен `account_id` — идентификатор брокерского счёта; `currency` (`RUB` по
умолчанию, а также `USD`, `EUR`, `UNSPECIFIED`) задаёт валюту итогов.

**`find_instrument`** — поиск инструмента по тикеру, ISIN или названию. Обязателен
`query`; `instrument_kind` фильтрует по типу (`INSTRUMENT_TYPE_SHARE`, `…_BOND`,
`…_ETF`, `…_CURRENCY`, по умолчанию без фильтра), `api_trade_available_flag` (по
умолчанию `true`) оставляет только доступные для торговли через API. Возвращает FIGI —
ключ инструмента в системе.

Оба инструмента требуют `TINKOFF_INVEST_TOKEN` и ничего не изменяют.

## 5. Готовые сценарии

**1. «Выстави счёт на 3 500 за подписку.»**
`init_payment` (`amount: 3500`, `order_id: "sub-2026-09"`, `description`,
`customer_key`, `recurrent: "Y"`). Из ответа берут `PaymentURL` — ссылку для
плательщика — и `PaymentId` для дальнейших действий.

**2. «Оплатил ли клиент заказ?»**
`get_payment_state` (`payment_id`). Статус, сумма и `OrderId` приходят одним вызовом.

**3. «Заморозь деньги, спишем после отгрузки.»**
Двухстадийная схема настраивается на терминале. После оплаты плательщиком —
`get_payment_state` (убедиться, что средства удержаны) → `confirm_payment`
(`payment_id`, при частичной отгрузке — `amount` меньше удержанного). Если отгрузки не
будет — `cancel_payment`.

**4. «Верни клиенту половину заказа.»**
`get_payment_state` (проверить, что платёж подтверждён, и увидеть сумму) →
`refund_payment` (`payment_id`, `amount` — половина) → снова `get_payment_state`.

**5. «Спиши подписку с сохранённой карты.»**
`get_card_list` (`customer_key`, взять `RebillId` нужной карты) → `charge_payment`
(`payment_id` исходного платежа с `recurrent: "Y"`, `rebill_id`, при необходимости
`amount`). Подтверждения от плательщика не требуется — списание немедленное.

**6. «Дай QR-код СБП на оплату 1 200.»**
`init_payment` (`amount: 1200`, `order_id`) → `create_sbp_qr` (`payment_id`,
`data_type: "IMAGE"` для картинки или `PAYLOAD` для ссылки) → периодически
`get_sbp_qr_state` (`payment_id`) до появления оплаты.

**7. «Отгрузили товар — отправь закрывающий чек.»**
`send_closing_receipt` (`payment_id`, `taxation: "usn_income"`, `email`,
`items: [{Name, Price, Quantity, Amount, Tax: "vat20"}]`). `Amount` позиции должен
равняться `Price × Quantity`.

**8. «Покажи, что в портфеле.»**
`get_invest_portfolio` (`account_id`, `currency: "RUB"`). Для расшифровки бумаг —
`find_instrument` по тикеру.

**9. «Отвяжи карту клиента.»**
`get_card_list` (`customer_key`) → `remove_card` (`customer_key`, `card_id`). Чтобы
удалить покупателя вместе со всеми картами — `remove_customer`.

## 6. Ограничения и подводные камни

### 6.1 Суммы задаются в рублях

Все инструменты принимают рубли и переводят их в копейки сами. Передав `10050` вместо
`100.50`, вы выставите счёт на 10 050 рублей, и никакой ошибки не будет — сумма
допустима. Это самая дорогая опечатка в наборе.

Дробная часть округляется до копейки.

### 6.2 Два метода не повторяются автоматически — и это принципиально

Весь API T-Kassa работает методом POST, но обращается сервер с ними по-разному.

Метод `/Init` T-Kassa различает по вашему `OrderId` — повтор с тем же номером заказа не
создаёт второй платёж. Поэтому `init_payment`, как и все читающие вызовы, при `429`,
`5xx` и таймауте повторяется автоматически: до трёх попыток, задержка
`1000 × 2^(попытка−1)` мс, но не дольше 8 секунд.

А `/Cancel` и `/Charge` — то есть `cancel_payment`, `refund_payment` и
`charge_payment` — **не защищены ключом идемпотентности вообще**. Повтор возвращает
деньги второй раз или списывает с карты второй раз. Эти два метода при неоднозначном
сбое не повторяются, и к тексту ошибки дописывается:

> Повтор не выполнен автоматически: операция двигает деньги и не защищена ключом
> идемпотентности. Проверьте состояние через `get_payment_state`, прежде чем повторять.

Правило простое: увидели таймаут или `5xx` на возврате, отмене или списании по подписке —
сначала `get_payment_state`, и только потом решение о повторе. `5xx` здесь означает
«результат неизвестен», а не «ничего не произошло».

Таймаут одного запроса — 10 секунд, переменной окружения не настраивается.

### 6.3 Отмена и возврат — один метод API

`cancel_payment` и `refund_payment` отправляют одинаковый запрос на `/Cancel` с
`PaymentId` и необязательной суммой. Разница только в названии инструмента и его
описании. Что произойдёт фактически — снятие удержания или возврат списанных денег —
определяет текущий статус платежа на стороне T-Kassa.

Следствие: выбор «того самого» инструмента не защищает от ошибки. Защищает проверка
статуса перед вызовом.

### 6.4 Ошибка может прийти с кодом 200

T-Kassa отвечает `HTTP 200` и на логические отказы: в теле приходит `Success: false` с
полями `ErrorCode`, `Message` и `Details`. Сервер разбирает такой ответ и превращает его
в ошибку вида `T-Kassa [<код>]: <сообщение> (<детали>)` — успехом он его не считает.

Ответы с `ErrorCode: "0"` считаются успешными даже при `Success: false`.

### 6.5 Т-Инвестиции — отдельный контур без повторов

Инструменты `get_invest_portfolio` и `find_instrument` используют собственный клиент:
другой адрес (`invest-public-api.tinkoff.ru/rest`), другая авторизация (Bearer-токен),
**без повторов и без таймаута**. Сбой сети или `5xx` возвращаются сразу. Это допустимо,
потому что оба инструмента только читают.

Токен проверяется в момент вызова, а не при старте: без `TINKOFF_INVEST_TOKEN` остальные
четырнадцать инструментов работают как обычно.

### 6.6 Чего в наборе нет

- **Списка платежей.** Инструмента «покажи все платежи за период» не существует —
  T-Kassa адресуется по `PaymentId` и `OrderId`. Реестр операций смотрят в личном
  кабинете.
- **Списка покупателей.** `get_customer` работает по известному `customer_key`;
  перебрать всех нельзя.
- **Работы с уведомлениями.** Подписки на события задаются полем `notification_url`
  конкретного платежа либо настройками терминала, отдельных инструментов для них нет.
- **Списка брокерских счетов** для Т-Инвестиций: `account_id` берут в профиле.

### 6.7 Объём ответа и фильтрация текста

Ответ длиннее 50 000 символов обрезается с пометкой о срезке. Практически это касается
только `get_invest_portfolio` на большом портфеле и `find_instrument` с широким запросом
— сузьте `instrument_kind`.

Тексты из ответов проходят фильтр: конструкции вида «игнорируй предыдущие инструкции» и
теги `<system>` заменяются на `[filtered]`. Отключается переменной
`MCP_DISABLE_SANITIZE=true`.

Отдельное замечание для `create_sbp_qr` с `data_type: "IMAGE"`: ответ содержит
изображение в base64 и занимает десятки килобайт. Если картинка не нужна, берите
`PAYLOAD`.

## 7. Частые ошибки

| Что видно | Что это значит | Что делать |
|---|---|---|
| `Переменные окружения TKASSA_TERMINAL_KEY и TKASSA_PASSWORD обязательны…` | Ключи не дошли до процесса; проявляется при первом вызове платёжного инструмента | Задать обе переменные в блоке `env` и перезапустить клиент |
| `T-Kassa [9999]: Неверные параметры` (и подобные коды) | Логический отказ: неверный `PaymentId`, недопустимый статус для операции, ошибка в составе чека | Прочитать `Message` и `Details` — они приходят от T-Kassa как есть; проверить статус через `get_payment_state` |
| Ошибка про `Token` или неверную подпись | Пароль терминала не соответствует ключу | Сверить пару `TKASSA_TERMINAL_KEY` / `TKASSA_PASSWORD` в кабинете: Магазины → Терминалы |
| `T-Kassa HTTP 403` | Терминал не имеет права на операцию (например, двухстадийная схема или СБП не подключены) | Подключить нужную схему на терминале в кабинете |
| `T-Kassa HTTP 404` | Неверный путь либо платёж не существует в этом контуре | Проверить `payment_id`; тестовый и боевой терминалы не пересекаются |
| `T-Kassa HTTP 429` | Лимит запросов; для повторяемых методов три попытки уже израсходованы | Пауза, снизить частоту |
| `T-Kassa HTTP 5xx` (для `/Init` и чтения) | Сбой на стороне T-Kassa, три попытки израсходованы | Повторить позже |
| `T-Kassa HTTP 5xx … Повтор не выполнен автоматически: операция двигает деньги…` | Сбой на `cancel_payment`, `refund_payment` или `charge_payment`; результат неизвестен | **Не повторять вслепую.** `get_payment_state`, затем решение |
| `T-Kassa: request timeout (10s).` | Ответ не пришёл за 10 секунд. Для повторяемых методов — три попытки исчерпаны | Для чтения повторить; для денежных методов — сначала `get_payment_state` |
| `T-Kassa: all retries exhausted` | Три попытки подряд закончились повторяемой ошибкой | Проверить доступность API; продолжать повторы бессмысленно |
| `TINKOFF_INVEST_TOKEN не задан…` | Вызван инструмент Т-Инвестиций без токена | Создать токен: приложение Т-Инвестиций → Настройки → Токен для OpenAPI |
| `T-Invest API <путь> → 401: …` | Токен Т-Инвестиций не принят | Выпустить новый токен; ключ T-Kassa здесь не подходит |
| `T-Invest API <путь> → 400: …` | Неверный `account_id` или параметры запроса | Взять идентификатор счёта в профиле Т-Инвестиций |
| `Ошибка валидации: amount: …` | Проверка параметров: сумма не положительная либо не число | Передавать сумму **в рублях** положительным числом |
| Сумма оказалась в сто раз больше | Переданы копейки вместо рублей | Раздел 6.1: сервер переводит рубли в копейки сам |
| Возврат прошёл дважды | Повтор `refund_payment` после неоднозначного сбоя | Раздел 6.2: перед повтором обязателен `get_payment_state` |

Журнал сервера идёт в **stderr** — stdout занят протоколом JSON-RPC. Туда же пишутся
строки повторов (`<код> from <путь>, retry in <N>ms`, `Timeout <путь>, retrying`) и
ошибки обращений к API Т-Инвестиций.

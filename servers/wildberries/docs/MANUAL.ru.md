## 1. Что это и кому нужно

Сервер даёт ИИ-агенту прямой доступ к кабинету продавца Wildberries: карточки товаров, цены,
остатки FBS и FBW, заказы, поставки, отчёт о реализации, воронка продаж, отзывы, вопросы,
возвраты и рекламные кампании. Продавец формулирует задачу словами — «покажи неотвеченные
вопросы», «пересчитай ABC за месяц», «собери поставку из новых заказов» — и агент выполняет
её вызовами API, не открывая веб-кабинет и не выгружая Excel. Данные нигде не кэшируются:
каждый вызов — запрос к живому API Wildberries и возврат его ответа.

Продукт не является ни аналитической системой, ни складским учётом; он не создаёт карточки
товаров, не редактирует их содержимое и не управляет ставками в рекламе — только те 30
операций, что перечислены в разделе 4.

## 2. Установка и подключение

Конфигурации ниже запускают пакет через `npx` — при каждом старте нужен доступ к реестру npm.
Альтернатива: `npm install -g @theyahia/wildberries-mcp`, тогда в поле `command` указывается
`wildberries-mcp`, а `args` остаётся пустым.

### Claude Desktop

Файл `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "wildberries": {
      "command": "npx",
      "args": ["-y", "@theyahia/wildberries-mcp"],
      "env": { "WB_API_TOKEN": "ваш_токен_продавца" }
    }
  }
}
```

После правки файла клиент перезапускается — конфигурация читается только при старте.
Переменные окружения ОС дочернему процессу могут не наследоваться, поэтому токен задаётся
именно в блоке `env`.

### Claude Code

`claude mcp add wildberries -e WB_API_TOKEN=ваш_токен -- npx -y @theyahia/wildberries-mcp`

### Cursor / Windsurf / VS Code (Copilot)

Cursor и Windsurf принимают тот же блок `mcpServers` в своих настройках MCP. У VS Code
конфигурация лежит в `.vscode/mcp.json` рабочей области, и корневой ключ там — `servers`,
а не `mcpServers`; поля `command`, `args` и `env` те же. Файл рабочей области обычно попадает
под контроль версий — токен в нём хранить не следует.

### Режим Streamable HTTP

```bash
HTTP_PORT=3000 WB_API_TOKEN=ваш_токен npx @theyahia/wildberries-mcp
# либо: npx @theyahia/wildberries-mcp --http   (порт 3000 по умолчанию)
```

Эндпоинты: `POST /mcp` (запросы; инициализация создаёт сессию), `GET /mcp` (поток SSE),
`DELETE /mcp` (завершение сессии), `GET /health` (состояние процесса: `status`, `server`,
`version`, `uptime`, `memory_mb`, `tools`). Сессии различаются заголовком `mcp-session-id`;
кросс-доменные браузерные вызовы по умолчанию запрещены. Собственной аутентификации у `/mcp`
нет: доступ к порту равносилен доступу к кабинету продавца — только внутренний контур или
обратный прокси со своей аутентификацией.

### Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `WB_API_TOKEN` | да | Токен Seller API (JWT). Без него процесс завершается с кодом 1 сразу при старте |
| `WB_TIMEOUT_MS` | нет | Таймаут одного запроса, мс. По умолчанию 30000 |
| `HTTP_PORT` | нет | Если задана — сервер стартует в режиме HTTP на этом порту |
| `MCP_DISABLE_SANITIZE` | нет | `true` отключает фильтрацию ответов от инъекций (см. 6.6) |

## 3. Где взять токен

1. Открыть кабинет продавца: `https://seller.wildberries.ru/supplier-settings/access-to-api`
   (Настройки → Доступ к API) — этот адрес зашит в сообщение об ошибке при пустом токене.
2. Создать токен и отметить нужные **категории доступа**. Категория — не формальность: каждый
   инструмент обращается к своему хосту, и токен без нужной категории вернёт `401` **от этого
   хоста**, тогда как остальные инструменты продолжат работать.
3. Скопировать токен в поле `env` конфигурации клиента.

| Категория доступа | Какие инструменты работают |
|---|---|
| Контент | `list_products`, `get_product` |
| Цены и скидки | `update_prices` |
| Маркетплейс | `update_stocks`, `get_stocks`, `get_orders`, `get_new_orders`, `get_warehouses`, `get_supply`, `create_supply`, `add_orders_to_supply`, `deliver_supply`, `get_supply_barcode` |
| Статистика | `get_sales`, `get_incomes`, `get_fbw_stocks`, `get_statistics`, `get_abc_analysis` |
| Аналитика | `get_funnel`, `get_paid_storage` |
| Тарифы | `get_commission`, `get_tariffs` |
| Отзывы и вопросы | `get_feedbacks`, `reply_feedback`, `get_questions`, `reply_question` |
| Возвраты | `get_returns` |
| Продвижение | `get_balance`, `list_campaigns`, `get_campaign_stats` |

Срок жизни токена в коде не проверяется; README сервера указывает 180 дней. Просроченный
токен проявится как `401` от всех хостов сразу.

## 4. Инструменты по задачам

API Wildberries — не единый шлюз. `seller.wildberries.ru` — это веб-кабинет, а не точка входа
API; запросы маршрутизируются по девяти хостам категорий, и сервер выбирает хост сам:
`content-api`, `discounts-prices-api`, `marketplace-api`, `statistics-api`,
`seller-analytics-api`, `common-api`, `feedbacks-api`, `returns-api`, `advert-api` — все в
домене `wildberries.ru`. Имя хоста попадает в текст любой ошибки, поэтому по нему сразу видно,
какой категории доступа не хватает токену.

Результат возвращается как JSON с отступами — ответ API в исходном виде, кроме
`get_abc_analysis` (расчёт на стороне сервера) и трёх инструментов поставок, отдающих
короткую сводку о выполненном действии.

### 4.1 Посмотреть товары

**`list_products`** — постраничный список карточек. Обязательных параметров нет: `limit`
(1–100, по умолчанию 100), `cursor` (значение `updatedAt` из предыдущего ответа), `textSearch`
(подстрока в названии). Внутри проставляется фильтр `withPhoto: -1` — карточки и с фото, и без.

**`get_product`** — подробности карточек. Обязателен `nmIDs` — массив номенклатурных ID,
от 1 до 100 штук.

### 4.2 Изменить цены и остатки

**`update_prices`** — обязательный `prices`: массив объектов `{nmID, price}`, минимум один
элемент, `price` — целое число рублей, не меньше нуля. Создаёт **асинхронную задачу загрузки**:
успешный ответ означает, что задача принята, а не что цены уже изменились.

**`update_stocks`** — остатки FBS на складе. Обязательны `warehouseId` (из `get_warehouses`)
и `stocks` — массив `{sku, amount}`, где `sku` — штрихкод, `amount` — целое количество.

**`get_stocks`** — текущие остатки FBS. Обязателен `warehouseId`; `skus` — массив штрихкодов,
пустой или отсутствующий означает «все остатки склада». **`get_fbw_stocks`** — остатки на
складах Wildberries (FBW), обязателен `dateFrom` (RFC3339): другой хост и другая модель
хранения, напрямую с `get_stocks` не сравниваются.

### 4.3 Разобрать заказы и продажи

**`get_new_orders`** — новые (несобранные) сборочные задания FBS; параметров нет.
**`get_orders`** — все заказы FBS, все параметры необязательны: `limit` (1–1000), `next`
(курсор), `dateFrom`, `dateTo` (RFC3339, например `2026-01-01T00:00:00Z`).

**`get_sales`** — отчёт о продажах. Обязателен `dateFrom`; `dateTo` необязателен; `flag` = 0
(все записи за период) или 1 (только новые с прошлого запроса). **`get_incomes`** — поставки,
принятые складами Wildberries; обязателен `dateFrom`.

### 4.4 Собрать и отгрузить поставку FBS

Порядок вызовов фиксирован: склад → поставка → задания → отгрузка → этикетка.

**`get_warehouses`** — список складов (офисов), параметров нет; отсюда берётся `warehouseId`
для остатков. **`get_supply`** — список поставок, `limit` (1–1000) и `next` необязательны.

**`create_supply`** — создать поставку. Обязателен `name`; возвращает идентификатор вида `WB-GI-1234567`.

**`add_orders_to_supply`** — прикрепить сборочные задания. Обязательны `supplyId` и `orderIds`
(массив чисел, минимум одно). Wildberries принимает **одно задание на запрос**, поэтому сервер
выполняет цикл последовательных PATCH-вызовов и возвращает `{supplyId, added}`. При сбое на
середине списка часть заданий уже прикреплена — повторять нужно только оставшиеся.

**`deliver_supply`** — закрыть поставку и передать в доставку. Обязателен `supplyId`; заказы
переходят в статус «в доставке», отменить операцию инструментами сервера нельзя.

**`get_supply_barcode`** — QR-этикетка поставки. Обязателен `supplyId`; `type` — `svg`
(по умолчанию), `zpl` или `png`. Доступна только после `deliver_supply`.

### 4.5 Считать аналитику

**`get_statistics`** — детальный отчёт о реализации (`/api/v5/supplier/reportDetailByPeriod`).
Обязательны `dateFrom` и `dateTo` (RFC3339); `limit` до 100000, `rrdid` — курсор (значение
`rrd_id` последней строки). Отчёт длинный: без курсора придёт только первая порция.

**`get_abc_analysis`** — ABC-разбор по выручке. Обязательны `dateFrom` и `dateTo`. Считается
на стороне сервера по тому же отчёту о реализации (`limit=100000`, `rrdid=0`): строки
группируются по `nm_id`, суммируются `retail_amount` и `quantity`, список сортируется по
убыванию выручки, накопленная доля до 80 % — класс **A**, до 95 % — **B**, остальное — **C**.
Возвращает `summary` (`totalProducts`, `totalRevenue`, счётчики классов) и `items` с полями
`nmId`, `name`, `revenue`, `orders`, `revenueShare`, `class`.

**`get_funnel`** — воронка: просмотры, корзина, заказы, выкупы. Обязательны `dateFrom` и
`dateTo` **в формате `YYYY-MM-DD`** (не RFC3339, в отличие от статистики); `page` (с 1) и
`nmIDs` необязательны.

**`get_paid_storage`** — отчёт о платном хранении. Обязательны `dateFrom` и `dateTo`
(RFC3339). Асинхронный: сервер создаёт задачу, опрашивает статус каждые 5 секунд до значения
`done`, затем скачивает отчёт и возвращает `{taskId, report}`. Предел ожидания — 120 секунд,
при превышении возвращается ошибка `pollUntil timed out`.

**`get_commission`** — комиссии по категориям; `locale` — `ru` (по умолчанию), `en`, `zh`. **`get_tariffs`** — тарифы коробов (логистика и хранение); `date` в формате `YYYY-MM-DD`, по умолчанию сегодняшняя.

### 4.6 Отвечать на отзывы и вопросы

**`get_feedbacks`** — отзывы; все параметры необязательны: `isAnswered`, `take` (1–5000),
`skip`, `order` (`dateAsc` / `dateDesc`). **`get_questions`** — вопросы покупателей:
`isAnswered` (по умолчанию `false`), `take` (1–10000, по умолчанию 100), `skip` (0), `order`.

**`reply_feedback`** и **`reply_question`** — публикация ответа. У обоих обязательны `id` и
`text`; у `reply_question` есть `state` со значением `wbRu` по умолчанию (публикация), прочие
допустимые значения в коде не подтверждены.

### 4.7 Возвраты и реклама

**`get_returns`** — заявки покупателей на возврат; `isArchive` (по умолчанию `false`), `limit` (1–200), `offset`, `nmId` — все необязательны.

**`get_balance`** (баланс и бонусы рекламного счёта) и **`list_campaigns`** (сводка кампаний по типам и статусам) параметров не принимают.

**`get_campaign_stats`** — статистика кампаний. Обязательны `campaignIds` (массив чисел,
минимум один), `dateFrom` и `dateTo` в формате `YYYY-MM-DD`.

## 5. Готовые сценарии

Формат: фраза пользователя → цепочка вызовов → на что смотреть.

**1. «Покажи первые 50 карточек с текущими ценами.»** — `list_products` (`limit: 50`) → при
необходимости `get_product` с полученными `nmID`. Цены отдаёт контентный хост; отдельного
инструмента «получить цену» нет.

**2. «Сделай ABC-анализ за 30 дней — какие товары дают 80 % выручки.»** — `get_abc_analysis`
(`dateFrom`, `dateTo` в RFC3339). Класс A в `summary` и есть искомые позиции. Расчёт идёт по
отчёту о реализации, то есть по фактическим продажам, а не по заказам.

**3. «Собери поставку из новых заказов, закрой её и дай этикетку.»** — `get_new_orders` →
`create_supply` (`name`) → `add_orders_to_supply` (`supplyId`, `orderIds`) → `deliver_supply`
→ `get_supply_barcode`. Шаги 3–5 необратимы средствами сервера.

**4. «Обнови остатки на складе по прайсу из файла.»** — `get_warehouses` (взять
`warehouseId`) → `update_stocks` с массивом `{sku, amount}`. `sku` — штрихкод, а не
номенклатурный ID: перепутанные значения даст ошибку API, а не схемы.

**5. «Подними цену на 10 % у товаров класса C.»** — `get_abc_analysis` → отобрать `nmId` с
`class: "C"` → `get_product` (текущие цены) → `update_prices`. Ответ подтверждает приём
задачи; применение проверяется повторным `get_product`.

**6. «Покажи неотвеченные вопросы и подготовь ответ на первый.»** — `get_questions`
(`isAnswered: false`) → `reply_question` (`id`, `text`). Текст публикуется сразу —
промежуточного «черновика» в API нет.

**7. «Какие товары часто возвращают и что о них пишут в отзывах?»** — `get_returns`
(`limit: 200`) → сгруппировать по `nmId` → `get_feedbacks`. Связь между заявкой на возврат и
отзывом строит агент по `nmId`, сервер её не выводит.

**8. «Сколько денег на рекламе и какие кампании активны?»** — `get_balance` →
`list_campaigns` → `get_campaign_stats` (`dateFrom` / `dateTo` в формате `YYYY-MM-DD`).

## 6. Ограничения и подводные камни

### 6.1 Ограничение частоты запросов и штраф 409

Wildberries считает лимиты **по категориям API**, а не одним общим счётчиком, и отвечает
`409` как штрафом за всплеск. Поэтому сервер держит отдельный ограничитель (token bucket) на
каждый хост и ещё несколько — на отдельные строгие эндпоинты. Ключи и значения:

| Ключ ограничителя | Запросов в минуту | Минимальный интервал |
|---|---|---|
| `content-api` | 100 | 120 мс |
| `discounts-prices-api` | 100 | 600 мс (≈10 запросов за 6 с) |
| `marketplace-api` | 300 | 200 мс |
| `statistics-api` | 60 | 600 мс |
| `feedbacks-api` | 60 | 600 мс |
| `seller-analytics-api` | 60 | 1000 мс |
| `common-api` | 60 | 1000 мс |
| `returns-api` | 100 | 300 мс |
| `advert-api` | 60 | 1000 мс |
| `paid_storage:create` | 1 | 1000 мс |
| `paid_storage:download` | 1 | 1000 мс |
| `paid_storage:status` | 12 | 5000 мс |
| `advert:balance` | 60 | 1000 мс |
| неизвестный ключ (запас) | 300 | 200 мс |

Перед каждым запросом ограничитель ждёт выполнения обоих условий: прошёл минимальный интервал
и в корзине есть хотя бы один токен. Корзина пополняется линейно, `rpm / 60000` токенов за
миллисекунду; ожидания пишутся в stderr строками
`[wildberries-mcp rate-limiter] Throttling: waiting …ms`.

Обработка `409` состоит из трёх действий. **Штраф** — из корзины провинившейся категории
списывается 5 токенов (не опускаясь ниже нуля). **Синхронизация** — читается заголовок
`X-Ratelimit-Remaining`, и если он разбирается как число, запас токенов урезается до этого
значения: сервер доверяет счётчику Wildberries больше, чем своему. **Пауза** — читается
`X-Ratelimit-Retry-After` (секунды, дробные допускаются) и переводится в миллисекунды; без
заголовка пауза 1000 мс. После паузы запрос повторяется.

Штраф изолирован: `409` на хосте отзывов не тормозит работу с заказами. Значения в таблице,
кроме документированных Wildberries строгих эндпоинтов платного хранения и цен, выбраны
осторожно; поднять их можно только правкой кода — переменных окружения для этого нет.

### 6.2 Повторы и таймауты

Максимум повторов — 3 (до 4 попыток на вызов). Повторяются `409` (после вычисленной паузы),
ответы `5xx` и сетевые сбои — с задержкой `1000 × (номер попытки + 1)` мс. Ответы `4xx`,
кроме `409`, не повторяются никогда: это ошибка запроса, а не сбой связи.

**Таймаут не повторяется** — прерывание по времени уже израсходовало весь бюджет ожидания, и
повтор лишь умножил бы задержку. По умолчанию таймаут 30 секунд, меняется переменной
`WB_TIMEOUT_MS`; тяжёлые отчёты (`get_statistics` за длинный период, `get_paid_storage`) —
первые кандидаты на его увеличение.

### 6.3 Пагинация — пять несовместимых механизмов

| Инструменты | Механизм |
|---|---|
| `list_products` | Курсор `cursor` = значение `updatedAt` из предыдущего ответа |
| `get_orders`, `get_supply` | Курсор `next` (число) |
| `get_statistics`, `get_abc_analysis` | Курсор `rrdid` = `rrd_id` последней строки |
| `get_feedbacks`, `get_questions` | Смещение: `take` + `skip` |
| `get_returns` | Смещение: `limit` + `offset` |
| `get_funnel` | Номер страницы `page`, с единицы |

Единой схемы нет — это устройство самого API Wildberries. Агент, привыкший к `offset`, на
`list_products` молча получит одну и ту же первую страницу.

### 6.4 Форматы дат тоже разные

RFC3339 (`2026-01-01T00:00:00Z`) требуют `get_orders`, `get_sales`, `get_incomes`,
`get_fbw_stocks`, `get_statistics`, `get_abc_analysis`, `get_paid_storage`; `YYYY-MM-DD` —
`get_funnel`, `get_tariffs`, `get_campaign_stats`. Формат не той группы даёт `400` от API.

### 6.5 Асинхронные операции и фильтрация ответов

`update_prices` возвращает подтверждение созданной задачи загрузки, а не изменённые цены;
инструмента опроса статуса этой задачи нет — результат проверяется повторным чтением
карточки. `get_paid_storage`, напротив, опрашивает статус сам, поэтому его вызов может занять
до двух минут.

Тексты отзывов и вопросов написаны покупателями — это поверхность для инъекции инструкций в
модель. Все ответы проходят через фильтр: конструкции вида «игнорируй предыдущие инструкции»,
«ты теперь…» и теги `<system>` заменяются на `[filtered]`, а ответ длиннее 50 000 символов
обрезается с пометкой о срезке. Отключается переменной `MCP_DISABLE_SANITIZE=true` — для
этого сервера отключать не следует.

### 6.6 Что в коде помечено как непроверенное

В исходниках стоят отметки `VERIFY` на местах, где форма запроса или ответа не сверялась с
актуальной документацией на живом токене: `get_supply_barcode` (форма ответа),
`reply_question` (значения `state`, кроме `wbRu`), `get_returns` (имена query-параметров),
`get_funnel` (имена полей тела запроса), `get_paid_storage` (строка статуса `done` и конверт
загрузки), `list_campaigns` (форма ответа; для полного списка кампаний может потребоваться
другой эндпоинт), `get_campaign_stats` (тело запроса `/adv/v2/fullstats`), `get_statistics`
(путь версии 5; преемник при её отключении — `POST /api/finance/v1/sales-reports/...`).

Если один из этих инструментов возвращает `400` с жалобой на структуру запроса, причина
скорее здесь, чем в ваших аргументах.

## 7. Частые ошибки

Ошибка возвращается модели как результат с признаком `isError: true` и текстом вида:

```
Error: WB API GET advert-api.wildberries.ru/adv/v1/balance → 401: <текст> (requestId=…)
```

В сообщении всегда есть метод, хост, путь и статус — по хосту сразу видно, какой категории
доступа не хватает. Из тела ответа сервер достаёт первое найденное поле `errorText`, `detail`,
`title`, `message` или `error`, а также `requestId` (или `request_id`), если он есть.
Неразбираемое тело обрезается до 500 символов.

| Что видно | Что это значит | Что делать |
|---|---|---|
| `→ 401` от одного хоста, остальные инструменты работают | У токена нет категории доступа именно этой группы | Добавить категорию токену в кабинете (таблица в разделе 3) |
| `→ 401` от всех хостов | Токен недействителен, отозван или истёк | Выпустить новый токен |
| `→ 403` | Категория есть, но операция запрещена аккаунту | Проверить права продавца в кабинете |
| `→ 409` в тексте ошибки (после всех попыток) | Штраф за превышение частоты не удалось переждать за 4 попытки | Пауза в несколько минут; проверить, не ходит ли параллельно другая интеграция под тем же токеном |
| `timed out after 30000ms` | Ответ не пришёл за отведённое время; повтор не выполняется | Сузить период отчёта, поднять `WB_TIMEOUT_MS` |
| `network error: …` | Сбой соединения; выполнено до 3 повторов | Проверить связь и доступность хостов Wildberries |
| `pollUntil timed out after 120000ms (paid_storage …)` | Отчёт о хранении не сформировался за 2 минуты | Повторить позже; задача на стороне Wildberries могла остаться в очереди |
| `paid_storage: API did not return a taskId` | Ответ на создание задачи пришёл без идентификатора | Проверить категорию «Аналитика» у токена и корректность дат |
| `Ошибка валидации: <поле>: <причина>` | Аргументы не прошли проверку схемы **до** запроса к API | Исправить аргумент; сетевого вызова не было |
| `→ 400` с жалобой на структуру | Форма запроса разошлась с текущим API | Сверить с разделом 6.7 |
| Пустой список там, где данные ожидаются | Не тот механизм пагинации или не тот формат даты | Разделы 6.3 и 6.4 |
| `Unknown tool: <имя>` | Вызвано имя, которого нет среди 30 инструментов | Опечатка в имени инструмента |

Отдельно: `WB_API_TOKEN is required` в журнале при старте и немедленное завершение процесса
означают, что переменная не дошла до дочернего процесса — её задают в блоке `env`
конфигурации клиента, а не в окружении оболочки. Весь журнал сервера идёт в **stderr**:
stdout занят протоколом JSON-RPC.

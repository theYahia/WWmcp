# Руководство пользователя cdek-mcp

Пакет `@theyahia/cdek-mcp`, версия 2.2.0, 16 инструментов. Node.js 18 и выше.

## 1. Что это и кому нужно

Сервер даёт ИИ-агенту доступ к API СДЭК версии 2 на всём жизненном цикле отправления:
рассчитать стоимость и срок, создать заказ, вызвать курьера, напечатать квитанцию и
этикетку, отследить посылку, найти ближайший пункт выдачи, подписаться на уведомления о
смене статусов. Задача, которую это снимает, — переключение между вопросом клиента и
интерфейсом кабинета: «сколько будет доставка двухкилограммовой коробки из Москвы в
Новосибирск», «где ближайший ПВЗ к этому адресу», «где сейчас посылка 1234567890»
выполняются репликой в чате.

Ответы приходят на русском: сервер переименовывает поля ответа СДЭК в понятные ключи
(`стоимость_доставки`, `срок_мин_дней`, `номер_сдэк`), оставляя только значимые.

## 2. Установка и подключение

### Claude Desktop

Файл `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "cdek": {
      "command": "npx",
      "args": ["-y", "@theyahia/cdek-mcp"],
      "env": {
        "CDEK_CLIENT_ID": "ваш_client_id",
        "CDEK_CLIENT_SECRET": "ваш_client_secret",
        "CDEK_SANDBOX": "true"
      }
    }
  }
}
```

`CDEK_SANDBOX` со значением `true` переводит сервер на тестовый контур. Для боевой работы
переменную убирают или ставят любое другое значение. Клиент читает конфигурацию при старте —
после правки его нужно перезапустить.

### Claude Code

`claude mcp add cdek -e CDEK_CLIENT_ID=ваш_id -e CDEK_CLIENT_SECRET=ваш_секрет -- npx -y @theyahia/cdek-mcp`

### Cursor / Windsurf / VS Code (Copilot)

Cursor и Windsurf принимают тот же блок `mcpServers` в `.cursor/mcp.json` или
`.windsurf/mcp.json`. У VS Code конфигурация лежит в `.vscode/mcp.json`, и корневой ключ там —
`servers`, а не `mcpServers`; поля `command`, `args` и `env` те же. Файл рабочей области
обычно попадает в систему контроля версий — `CDEK_CLIENT_SECRET` в нём хранить не следует.

### Режим Streamable HTTP

```bash
HTTP_PORT=3000 npx @theyahia/cdek-mcp --http
```

Эндпоинты: `POST /mcp` (запросы; инициализация создаёт сессию), `GET /mcp` (поток SSE),
`DELETE /mcp` (завершение сессии), `GET /health` (`status`, `server`, `version`, `uptime`,
`memory_mb`, `tools`). Сессии различаются заголовком `mcp-session-id`; кросс-доменные
браузерные вызовы по умолчанию запрещены. Ключи берутся из окружения процесса и одни на все
сессии — все подключившиеся работают от имени одного договора СДЭК. Собственной
аутентификации у `/mcp` нет, а доступ к порту позволяет создавать и удалять реальные заказы:
публиковать его в недоверенной сети нельзя.

### Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `CDEK_CLIENT_ID` | да | Идентификатор клиента для OAuth |
| `CDEK_CLIENT_SECRET` | да | Секрет клиента для OAuth |
| `CDEK_SANDBOX` | нет | `true` — тестовый контур `api.edu.cdek.ru`; иначе боевой `api.cdek.ru` |
| `HTTP_PORT` | нет | Если задана — сервер стартует в режиме HTTP на этом порту |
| `MCP_DISABLE_SANITIZE` | нет | `true` отключает фильтрацию ответов от инъекций |

Отсутствие ключей обнаруживается не при старте, а при **первом вызове любого инструмента** —
клиент создаётся лениво. Сообщение прямо называет недостающие переменные и путь к ним в
кабинете.

## 3. Где взять ключи доступа

Ключи выдаются в личном кабинете СДЭК: `https://lk.cdek.ru` → **Интеграция → Ключи API**.
Этот путь сервер называет сам в сообщении об отсутствующих переменных. Нужны два значения —
`client_id` и `client_secret`.

Аутентификация — OAuth 2.0 в схеме client credentials, и всю работу с токеном сервер берёт
на себя: получает токен при первом запросе, кэширует его, обновляет заблаговременно (за
минуту до истечения), объединяет одновременные обновления в одно и повторяет запрос после
`401`, сбросив кэш. Отдельной переменной для токена нет и быть не должно.

**Тестовый контур.** При `CDEK_SANDBOX=true` сервер обращается к `api.edu.cdek.ru`. СДЭК
публикует общую тестовую пару для интеграторов; на момент написания README сервера она
такая:

```
client_id     EMscd6r9JnFiQ3bLoyjJY6eM78JrJceI
client_secret PjLZkKBHEiLK3YsjtNrt3TGNG0ahs3kh
```

Пару периодически меняют: если при `CDEK_SANDBOX=true` приходит `OAuth token error (HTTP
401) … invalid_client`, значит общая пара сменилась — запрашивайте собственные тестовые ключи
в том же разделе кабинета. Заказы тестового контура не существуют в боевом, и наоборот:
прежде чем разбираться, почему «заказ не находится», проверьте значение `CDEK_SANDBOX`.

## 4. Инструменты по задачам

Место отправления и назначения задаётся объектом с полями `code` (код города СДЭК),
`postal_code` (почтовый индекс) и `address` (адрес). **Хотя бы одно из `code` или
`postal_code` обязательно** — сервер проверяет это до обращения к API и в противном случае
отвечает подсказкой найти код через `get_cities`.

### 4.1 Найти город, регион, пункт выдачи

**`get_cities`** — справочник городов. Все параметры необязательны: `city` (подстрока),
`postal_code`, `country_codes` (коды стран через запятую, например `RU,KZ`), `size` (1–1000,
по умолчанию 50), `page` (с 0). Возвращает `код`, `город`, `регион`, `страна`, `индекс_фиас`.
С него начинается почти любой сценарий: `код` — это и есть `city_code` для расчёта и заказа.

**`get_regions`** — справочник регионов; необязательные `country_codes`, `region` (подстрока),
`size`, `page`. Возвращает `код_региона`, `регион`, `страна`, `префикс`.

**`list_delivery_points`** — пункты выдачи и постаматы. Параметры:

| Параметр | Значения | По умолчанию |
|---|---|---|
| `city_code` | код города СДЭК | — |
| `postal_code` | почтовый индекс | — |
| `type` | `PVZ`, `POSTAMAT`, `ALL` | `ALL` |
| `country_code` | код страны | `RU` |
| `latitude`, `longitude`, `radius_km` | координаты и радиус поиска | — |
| `size` | 1–1000 | 50 |
| `page` | с 0 | 0 |

Три гео-параметра задаются **только вместе**: при частичном наборе сервер отвечает ошибкой.
О том, как работает поиск по радиусу, — раздел 6.3.

Ответ по каждому пункту: `код`, `название`, `тип`, `город`, `адрес`, `индекс`,
`время_работы`, `примерочная`, `наличные`, `безнал`. В гео-режиме добавляются `координаты`
и `расстояние_км`.

### 4.2 Рассчитать доставку

**`calculate_tariff_list`** — все доступные тарифы маршрута; нужен, когда тариф заранее
неизвестен. Обязательны `from_location`, `to_location` и `packages` — массив мест, минимум
одно; у места обязателен `weight` **в граммах**, размеры `length`, `width`, `height` в
сантиметрах необязательны. Возвращает `код_тарифа`, `название`, `стоимость`, `срок_мин`,
`срок_макс`.

**`calculate_tariff`** — расчёт по конкретному тарифу: то же самое плюс обязательный
`tariff_code`. Основные коды названы в описании инструмента: 136 — посылка склад-склад,
137 — склад-дверь, 138 — дверь-склад, 139 — дверь-дверь. Возвращает `стоимость_доставки`,
`срок_мин_дней`, `срок_макс_дней`, `расчётный_вес_г` и `валюта`. Расчётный вес важен: СДЭК
берёт большее из фактического и объёмного, и без габаритов оценка окажется заниженной.

### 4.3 Оформить и вести заказ

**`create_order`** — создание заказа. Обязательны:

| Параметр | Что это |
|---|---|
| `tariff_code` | Код тарифа |
| `from_location`, `to_location` | Места отправления и назначения |
| `recipient` | `name` (ФИО) и `phones` — массив объектов `{number}`, минимум один; `email` необязателен |
| `packages` | Массив мест: `number` (номер места) и `weight` в граммах обязательны |

У места необязательны габариты и `items` — вложения, где у каждой позиции требуются `name`,
`ware_key` (артикул), `cost` (объявленная стоимость), `weight` и `amount`, а `payment.value`
(наложенный платёж) необязателен. Для международных отправлений вложения обязательны.
Необязательный `comment` — комментарий к заказу.

Ответ содержит `uuid`, `cdek_number`, `статус_запроса` и напоминание проверить обработку
через `get_order`. Подробности о том, почему номер накладной может прийти пустым, — в
разделе 6.2.

**`get_order`** — заказ по UUID. Обязателен `uuid`. Возвращает `uuid`, `номер_сдэк` и
массив `статусы` с кодом, названием, датой и городом каждого.

**`list_orders`** — поиск заказов. Все параметры необязательны: `date_invoice_from` и
`date_invoice_to` (формат `YYYY-MM-DDTHH:MM:SS±HH:MM`), `im_number` (номер заказа
интернет-магазина), `cdek_number` (накладная), `size` (1–1000, по умолчанию 50), `page`.
Единственный инструмент, отдающий ответ СДЭК без переработки.

**`delete_order`** — удаление заказа по `uuid`. Работает **только пока заказ не передан
курьерской службе**; восстановить удалённый заказ нельзя.

**`track_shipment`** — отслеживание по номеру накладной. Обязателен `cdek_number`; возвращает
`номер`, `uuid`, `последний_статус` и полный массив `все_статусы`. Если известен только UUID,
а не накладная, используйте `get_order`.

### 4.4 Печать и вызов курьера

**`generate_barcode`** — этикетка со штрихкодом. Обязателен `uuid` заказа; `copy_count`
(1–10, по умолчанию 1) и `format` (`A4`, `A5`, `A6`; по умолчанию `A4`) необязательны.
Операция асинхронная: возвращается подтверждение приёма запроса, а **ссылка на PDF появляется
в результатах `get_order`**.

**`print_receipt`** — квитанция (накладная) в PDF. Обязателен `order_uuid`; `copy_count`
(1–10) необязателен. В отличие от этикетки, здесь сервер сам ждёт готовности: опрашивает
СДЭК пять раз с интервалом в 2 секунды, то есть до 10 секунд. Если файл готов — возвращает
`url`; если нет — `uuid` и сообщение, что квитанция формируется и её нужно проверить позже.

**`create_courier_pickup`** — заявка на вызов курьера. Обязательны `order_uuid`,
`intake_date` (`YYYY-MM-DD`), `intake_time_from` и `intake_time_to` (`HH:MM`).
Необязательны `name` (ФИО отправителя), `phone` и `comment` для курьера.

**`get_courier_pickup`** — статус заявки по её `uuid` (не UUID заказа): дата, интервал
времени, номер СДЭК и история статусов заявки.

### 4.5 Уведомления

**`create_webhook`** — подписка на уведомления. Обязательны `url` (СДЭК шлёт на него POST;
описание требует HTTPS) и `type` — `ORDER_STATUS` (смена статусов заказов) либо
`DOWNLOAD_PHOTO` (готовность фотографий). **`delete_webhook`** — удаление подписки по `uuid`
(проверяется как корректный UUID). Сменить адрес подписки нельзя — старую удаляют и создают
новую.

## 5. Готовые сценарии

**1. «Сколько стоит отправить коробку 2 кг из Москвы в Петербург?»**
`get_cities` (`city: "Москва"`) и `get_cities` (`city: "Санкт-Петербург"`) → взять коды →
`calculate_tariff_list` (`from_location: {code: …}`, `to_location: {code: …}`,
`packages: [{weight: 2000}]`). Вес в **граммах**: 2 кг — это 2000.

**2. «Где ближайший ПВЗ к Красной площади?»**
`get_cities` (`city: "Москва"`) → `list_delivery_points` (`city_code`, `latitude: 55.7539`,
`longitude: 37.6208`, `radius_km: 5`). Результат отсортирован по расстоянию, у каждого
пункта есть `расстояние_км`.

**3. «Оформи доставку книги из Казани в Новосибирск.»**
`get_cities` по обоим городам → `calculate_tariff_list` (выбрать тариф) → `create_order`
(`tariff_code`, места, получатель с телефоном, `packages` с весом) → `get_order` по
полученному `uuid` для проверки, что заказ обработан и появился `номер_сдэк`.

**4. «Вызови курьера на завтра с 10 до 18 и распечатай квитанцию.»**
`create_courier_pickup` (`order_uuid`, `intake_date`, `intake_time_from: "10:00"`,
`intake_time_to: "18:00"`) → `print_receipt` (`order_uuid`) → скачать PDF по `url`.
Если квитанция ещё формируется, повторить вызов через минуту.

**5. «Где посылка 1234567890?»**
`track_shipment` (`cdek_number: "1234567890"`). Достаточно одного вызова: и последний
статус, и вся история приходят вместе.

**6. «Покажи все заказы за прошлую неделю.»**
`list_orders` (`date_invoice_from: "2026-06-01T00:00:00+03:00"`,
`date_invoice_to: "2026-06-07T23:59:59+03:00"`, `size: 1000`). Смещение часового пояса в
формате даты обязательно.

**7. «Подпишись на статусы заказов и присылай их нам.»**
`create_webhook` (`url: "https://наш-сервер/cdek-hook"`, `type: "ORDER_STATUS"`). Адрес
должен быть доступен извне и принимать POST; проверить доставку уведомлений средствами
сервера нельзя.

**8. «Отмени заказ, курьер ещё не приезжал.»**
`get_order` (`uuid`, убедиться, что статусов передачи нет) → `delete_order` (`uuid`).
После передачи курьеру инструмент вернёт отказ от СДЭК — отменять придётся через кабинет.

## 6. Ограничения и подводные камни

### 6.1 Ошибки СДЭК приходят не как ошибки

У API СДЭК два разных способа сообщить о проблеме, и сервер обращается с ними по-разному.

**Транспортный сбой** — `401`, `404`, `429`, `5xx`, таймаут — возвращается модели как
результат с признаком `isError: true` и типовым текстом категории.

**Отказ по существу** — неверный тариф, недопустимый маршрут, заказ, который нельзя
удалить, — приходит в теле успешного ответа массивом `errors`, и сервер отдаёт его обычным
текстом вида `Ошибка создания заказа: [код] сообщение`, **без** признака ошибки. Формально
вызов удался, содержательно — нет.

Практический вывод: результат инструментов заказа, расчёта, печати и подписок нужно читать,
а не только проверять на факт ошибки. Строка, начинающаяся со слова «Ошибка», означает
отказ, даже если вызов считается успешным.

### 6.2 Заказ создаётся асинхронно

СДЭК принимает запрос в очередь: ответ на `create_order` содержит `статус_запроса` и `uuid`,
но `cdek_number` в этот момент может быть пустым, а сам заказ ещё не обработан. Проверка —
отдельным вызовом `get_order` по полученному `uuid`. То же относится к `generate_barcode`
(ссылка на PDF появится в `get_order`), `create_courier_pickup` и `create_webhook`.

Единственный инструмент, который ждёт готовности сам, — `print_receipt`: он опрашивает СДЭК
до 10 секунд, и если файл не успел сформироваться, честно возвращает `uuid` с просьбой
проверить позже.

### 6.3 Гео-поиск ПВЗ считается на стороне клиента

У эндпоинта пунктов выдачи СДЭК **нет** серверного поиска по радиусу: координаты в запрос не
уходят. При заданных `latitude`, `longitude` и `radius_km` сервер запрашивает у СДЭК как
можно больше кандидатов (`size` поднимается минимум до 1000), считает расстояние по формуле
гаверсинуса и сам отфильтровывает и сортирует результат.

Отсюда два следствия. Первое: гео-поиск имеет смысл только вместе с `city_code` или
`postal_code` — иначе выборка кандидатов случайна относительно вашей точки. Второе: если в
городе пунктов больше тысячи, ближайший может не попасть в выборку. Расстояние —
по прямой, а не по дорогам.

### 6.4 Изменяющие операции не повторяются автоматически

Повторы выполняются только для запросов чтения (GET). Создание, изменение и удаление —
`create_order`, `delete_order`, `generate_barcode`, `print_receipt`,
`create_courier_pickup`, `create_webhook`, `delete_webhook`, а также оба расчёта тарифа
(они отправляются методом POST) — при таймауте, `5xx` или обрыве связи **не повторяются**,
и к тексту ошибки дописывается:

> Повтор не выполнен автоматически, потому что операция изменяет данные. Проверьте в базе,
> не создан ли объект, прежде чем повторять.

Для `create_order` это принципиально: повтор вслепую создаёт второй заказ на ту же
отправку. Прежде чем повторять, ищите заказ через `list_orders` по `im_number` или периоду.

Для чтения повторов не больше трёх, с задержкой `1000 × 2^(попытка−1)` мс, но не дольше
8 секунд. Таймаут одного запроса — 15 секунд, переменной окружения не настраивается.

### 6.5 Тестовый и боевой контуры не пересекаются

`CDEK_SANDBOX=true` меняет и адрес API, и адрес выдачи токена. Ключи одного контура не
работают в другом, объекты не видны между контурами. При запуске в тестовом режиме сервер
пишет об этом предупреждение в журнал (stderr) — если поведение выглядит странно, начните с
проверки этой строки.

### 6.6 Единицы измерения и форматы

| Что | Единица или формат |
|---|---|
| Вес места и товара | граммы |
| Габариты | сантиметры |
| Даты в `list_orders` | `YYYY-MM-DDTHH:MM:SS±HH:MM` (со смещением часового пояса) |
| Дата забора курьера | `YYYY-MM-DD` |
| Время забора | `HH:MM` |
| Объявленная стоимость и наложенный платёж | рубли, как принимает СДЭК |

Килограммы вместо граммов — самая частая ошибка расчёта: вес 2 вместо 2000 даёт стоимость
за двухграммовую посылку, и она проходит без всяких предупреждений.

### 6.7 Пагинация и объём ответа

Списочные инструменты (`get_cities`, `get_regions`, `list_delivery_points`, `list_orders`)
работают по схеме `size` + `page`, максимум 1000 записей на страницу, нумерация страниц с
нуля. Ответ длиннее 50 000 символов обрезается с пометкой о срезке — при выгрузке
справочника городов уменьшайте `size` и идите страницами.

Тексты из ответов (названия и адреса пунктов, комментарии) проходят фильтр: конструкции
вида «игнорируй предыдущие инструкции» и теги `<system>` заменяются на `[filtered]`.
Отключается переменной `MCP_DISABLE_SANITIZE=true`.

## 7. Частые ошибки

| Что видно | Что это значит | Что делать |
|---|---|---|
| `Переменные окружения CDEK_CLIENT_ID и CDEK_CLIENT_SECRET обязательны…` | Ключи не дошли до процесса. Появляется при первом вызове инструмента, а не при старте | Задать обе переменные в блоке `env` конфигурации клиента и перезапустить клиент |
| `OAuth token error (HTTP 401). Проверьте client_id и client_secret.` | Пара ключей не принята. В тестовом контуре — вероятная смена общей пары | Сверить ключи в `lk.cdek.ru` → Интеграция → Ключи API; для песочницы запросить свои |
| `OAuth token error (HTTP 400) … invalid_client` | То же самое, другой код от сервера выдачи токенов | То же |
| `Место отправления: укажите code … или postal_code …` | В объекте локации не задано ни то, ни другое | Найти код города через `get_cities` |
| `Для гео-поиска нужны все три параметра: latitude, longitude и radius_km.` | Задана часть гео-параметров | Дополнить набор или убрать его целиком |
| `Ошибка расчёта: [код] сообщение` | СДЭК отверг расчёт: недопустимый тариф для маршрута, неверные габариты | Прочитать код и сообщение; проверить `tariff_code` через `calculate_tariff_list` |
| `Нет доступных тарифов для данного маршрута.` | Расчёт прошёл, но вариантов нет | Проверить коды городов; для международных направлений — доступность направления по договору |
| `Ошибка создания заказа: [код] сообщение` | Заказ не создан. Частые причины — незаполненный обязательный реквизит, недопустимый тариф, отсутствие вложений для международной отправки | Исправить по тексту сообщения; **не повторять вызов вслепую** |
| `Ошибка удаления заказа: [код] сообщение` | Обычно заказ уже передан курьерской службе | Отменять через кабинет СДЭК |
| `Отправление <номер> не найдено.` | Накладной нет в этом контуре | Проверить номер и значение `CDEK_SANDBOX` |
| `Города не найдены по заданным параметрам.` / `Пункты выдачи не найдены…` / `Регионы не найдены…` | Запрос отработал, совпадений нет | Сократить строку поиска, проверить `country_codes` |
| `В радиусе N км от точки (…) пунктов выдачи не найдено.` | Кандидаты получены, но все дальше радиуса | Увеличить `radius_km`, убедиться, что задан `city_code` (раздел 6.3) |
| `Квитанция формируется. Проверьте позже по UUID.` | За 10 секунд файл не готов — это не ошибка | Повторить `print_receipt` позже |
| `Не удалось создать квитанцию: UUID не получен.` | Ответ на создание пришёл без идентификатора | Проверить, что `order_uuid` принадлежит существующему заказу |
| `Отказ в доступе (HTTP 401/403)` | Токен не обновился либо у договора нет прав на операцию | Проверить ключи; права уточнить у менеджера СДЭК |
| `Ресурс не найден` (404) | Неверный UUID заказа, заявки или вебхука | Найти заказ через `list_orders`; UUID заявки на курьера — не UUID заказа |
| `Таймаут запроса (15с)` | Ответ не пришёл вовремя | Для чтения повторить; для создания — сначала проверить, не создан ли объект |
| `Повтор не выполнен автоматически, потому что операция изменяет данные…` | Сбой на изменяющей операции, результат неизвестен | Раздел 6.4: проверить состояние через `list_orders` / `get_order` |
| `Rate limit. Повторите через Nс` (429) | Лимит СДЭК выбран | Пауза; уменьшить частоту вызовов и `size` |

Весь журнал сервера идёт в **stderr** — stdout занят протоколом JSON-RPC. В режиме песочницы
туда же пишется предупреждение `Using sandbox mode (CDEK_SANDBOX=true)`.

## [2.0.0] — 2026-06-23

Ломающий релиз: модель учётных данных изменилась с `POCHTA_TOKEN` + `POCHTA_KEY` на
`POCHTA_TOKEN` + `POCHTA_LOGIN` + `POCHTA_PASSWORD`.

### Fixed

Сервер был неработоспособен против реального API:

- **Заголовки авторизации были перепутаны.** `otpravka-api` требует
  `Authorization: AccessToken <token>` и `X-User-Authorization: Basic <base64(login:password)>`;
  старый код менял местами и расположение, и ключевое слово схемы — все REST-инструменты
  падали на авторизации. Исправлено в клиенте и `getAuth`.
- **URL отделений дублировали сегмент версии** (`.../1.0/postoffice/1.0/...`). Добавлена
  мультихостовая модель (otpravka `/1.0`, соседний postoffice `/1.0`, трекинг).
- **Несовпадение регистра полей ответа** (код читал snake_case, API отдаёт kebab-case) —
  результаты выходили пустыми. Инструменты читают ответ терпимо через `lib.ts`
  (`pick`/`asRecord`).
- **`track`**: убран вводящий в заблуждение REST-фоллбэк `/shipment/search` (он ищет по
  вашим собственным отправлениям, а не по публичному трекингу). Отслеживание по одному
  штрихкоду идёт через SOAP и требует `POCHTA_LOGIN` и `POCHTA_PASSWORD` — иначе
  понятная ошибка.

### Added

- HTTP-клиент: повторы с экспоненциальным backoff на сетевых сбоях, `429` и `5xx`,
  логирование в stderr, настраиваемый таймаут (`POCHTA_TIMEOUT_MS`).
- `src/version.ts` — единый источник версии (`createRequire`), убирает три хардкода;
  число инструментов вычисляется динамически.
- CI: матрица Node 18/20/22, кеш npm, шаг `typecheck`.
- Тесты 20 → 38: регрессия на контракт заголовков (поймала бы перепутанную авторизацию),
  маршрутизация по хостам, retry/таймаут, таблица `getAuth`, тесты инструментов с моком
  `fetch` (ловят баг регистра), smoke-тест сервера через `InMemoryTransport`.

### Changed

- Удалены неиспользуемые `express` и `@types/express`; в `files` добавлены `types`,
  README и `smithery.yaml`.
- README, `.mcp.json` и `smithery.yaml` приведены к корректному контракту, добавлена
  заметка о миграции.

### Известные ограничения

- Пути эндпоинтов и имена полей ответа для postoffice, tariff, delivery и clean/address
  реализованы по официальной документации и SDK и помечены в коде как `[VERIFY]`.

# /contacts-import — Список и импорт контактов

## Алгоритм

1. Вызови `get_lists` — проверь, нет ли уже подходящего списка. Дублирующий список
   разносит одну аудиторию по двум сегментам, и статистика после этого не сходится.
2. Если нужного списка нет — вызови `create_list` с title и опционально
   before_subscribe_url / after_subscribe_url (страницы до и после подтверждения подписки).
   Ответ содержит id списка.
3. Подготовь контакты. Каждый контакт — объект полей: обязательно email, дальше любые
   поля из настроек аккаунта (Name, Phone и т.п.).
4. По каждому контакту вызови `subscribe` с list_ids (ID списков строкой через запятую,
   например "1,2"), fields (объект полей контакта) и опционально
   double_optin и overwrite (0 — не перезаписывать, 1 — перезаписывать, 2 — дополнять).
5. Массового импорта в этом сервере нет — это один вызов на контакт. Для большого файла
   предупреди пользователя о времени до начала и отчитывайся о прогрессе.
6. Вызови `get_contacts` с list_id и limit — проверь, сколько реально легло в список.
   Ожидаемое и фактическое число должны совпасть; расхождение объясни.

## Формат ответа

```
## Импорт в UniSender

**Список**: «Клиенты сентябрь» (list_id 4471)

| Результат | Количество |
|-----------|-----------|
| добавлено | 312 |
| обновлено | 18 |
| ошибка формата email | 4 |

**В списке сейчас**: 330 контактов
```

## Важно

- double_optin определяет, попросит ли UniSender подтверждение подписки. Для холодной
  базы это обязательный шаг — без него рискуешь блокировкой аккаунта за жалобы.
- overwrite = 1 затирает существующие поля контакта. Уточни у пользователя, прежде чем
  ставить единицу на живой базе.
- list_ids — строка с ID через запятую, а не массив чисел.
- Рассылка по купленной базе нарушает правила UniSender и закон о рекламе. Если
  пользователь загружает список неизвестного происхождения — скажи об этом.

## Примеры

```
/contacts-import "Клиенты сентябрь" clients.csv
/contacts-import в список 4471 ivan@example.com Иван
```

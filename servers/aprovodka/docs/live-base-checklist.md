# Первый час на живой базе — что снять, пока доступ есть

Продукт ни разу не запускался на живой базе. Доступ — узкое место сразу для пяти
задач, и все они закрываются одним сеансом, если делать в этом порядке. Разбегаться
по вопросам на месте дорого: демо-доступ 1С:Фреш выдаётся на срок.

**Перед началом:** переменные те же, что у сервера.

```bash
export ONEC_BASE_URL='https://…/base'     # без /odata/standard.odata — скрипты допишут сами
export ONEC_LOGIN='…'
export ONEC_PASSWORD='…'
```

## 1. OData вообще опубликован? — WORK-1333, стоп-условие вехи 1

```bash
curl -sS -u "$ONEC_LOGIN:$ONEC_PASSWORD" "$ONEC_BASE_URL/odata/standard.odata/?\$format=json" | head -c 600
```

| Что вернулось | Вывод |
|---|---|
| JSON со списком `Catalog_…`, `Document_…` | OData включён — **да** |
| HTTP 401 | логин/пароль или у пользователя нет права на веб-сервисы |
| HTTP 404 / HTML веб-сервера | стандартный интерфейс OData не опубликован в Конфигураторе |

⛔ **Стоп-условие:** данные не идут и причина не устраняется за 4 часа → план
останавливается целиком, продавать сверку нечем.

**Записать в журнал** (`_Система/Research/onec-money-2026-08/99_ZHURNAL.md`, неделя 3):
`OData включён? да / нет`.

## 2. Расходует ли запрос сеанс? — WORK-1334, стоп-условие вехи 1

На тарифе «Базовый» 1С:Фреш сеансов **два**. Если каждый OData-запрос ест сеанс,
самый массовый сегмент технически непригоден, и вехи 3 и 5 пересобираются.

**Что уже известно из документации** (WORK-1334, сверка 03.09.2026 — сам замер это
не заменяет, счётчик Фреша и лицензия платформы это два разных счётчика):

- Лицензирование 1С, п. 10.2.5.8, дословно: «Для работы интернет-сервисов
  (Web-сервисы, HTTP-сервисы, **запросы к OData**) и фоновых заданий **не требуется
  клиентских лицензий**». То есть на уровне платформы запрос лицензию не берёт.
- 1С:Фреш меряет свой тариф иначе — «количество сеансов» описано как «сумма
  одновременно открытых всеми пользователями вкладок или окон тонкого клиента».
  Формулировка про интерактивного клиента, не про HTTP-запрос.
- Обе нормы указывают на «нет», но ни одна не является замером квоты Фреша.
  Проверяем именно её.

⚠️ **Замер делать параллельно, не подряд.** Десять запросов один за другим не
исчерпают пул из двух сеансов, даже если каждый запрос сеанс занимает: сеанс
закрывается раньше, чем открывается следующий. Последовательный прогон даст
ложное «не расходует». Нужен одновременный залп заведомо больше квоты.

1. Открыть базу в браузере и **оставить вкладку открытой** — это один сеанс из двух.
2. Дать залп из 5 одновременных запросов (при квоте 2 и одной занятой вкладке
   свободен один сеанс — залпа в 5 хватает с запасом):

```bash
for i in $(seq 1 5); do
  curl -s -o /dev/null -w '%{http_code}\n' -u "$ONEC_LOGIN:$ONEC_PASSWORD" \
    "$ONEC_BASE_URL/odata/standard.odata/?\$format=json" &
done; wait
```

3. Сразу же — список активных сеансов в личном кабинете сервиса.

| Что видно | Ответ |
|---|---|
| все 5 ответов `200`, в списке сеансов только браузерный, вкладку не выбило | **не расходует** |
| часть ответов не `200` (`406`, `503`, текст про превышение числа сеансов), либо в списке всплыли сеансы сверх браузерного, либо браузерную вкладку выбило | **расходует** |

`406 Not Acceptable` — задокументированный 1С отказ «не удалось создать сеанс»,
но документирован он для запросов с заголовком `IBSession: start`; обычный
OData-запрос при нехватке сеансов может упасть и иначе. Поэтому смотрим не только
на код, но и на список сеансов и на живость браузерной вкладки.

Повторить залп с `seq 1 10` — если при 5 всё чисто, а при 10 сыплется, потолок
существует и его нужно записать числом: это прямая калибровка `ONEC_MAX_CONCURRENCY`
(руководство, раздел 4.4) и всей рекомендации по тарифам.

**Записать в журнал:** `Расходует ли OData-запрос сеанс? да / нет` + при каком
числе одновременных запросов пошли отказы.

## 3. Снять фикстуры — WORK-1519

Пока доступ есть, снимается всё сразу: потом второго захода может не быть.

```bash
node scripts/capture-fixtures.mjs --config "БП 3.0" --platform "<из «О программе»>"
```

Имена сущностей конфигурационно-зависимы; свои задаются
`--catalog` / `--document` / `--register`.

Дальше — прогнать `parseOneCError` и `normaliseEntity` на снятом. **Всё, что упало,
— отдельный дефект**, а не повод править фикстуру под код.

## 4. Имя виртуальной таблицы оборотов Дт/Кт — WORK-1516

В снятом `tests/fixtures/02-metadata-fragment.xml` найти описание
`AccountingRegister_Хозрасчетный` и выписать **фактические** имена его виртуальных
таблиц.

```bash
grep -o 'AccountingRegister_[A-Za-zА-Яа-я_]*' tests/fixtures/02-metadata-fragment.xml | sort -u
```

Что с этим делать:

- имя нашлось (`DrCrTurnover` или `DrCrTurnovers`) → перенести его из
  `UNCONFIRMED_ACCOUNTING_TABLES` в `ACCOUNTING_VIRTUAL_TABLES`
  (`src/tools/accounting.ts`), поправить `_unsupported` в `src/presets/common.ts`,
  добавить тест на моке;
- не нашлось → оставить как есть. Инструмент уже объясняет, чего не хватает,
  и запрос с неподтверждённым именем в базу не отправляет.

Проверка на базе: обороты по конкретному счёту за месяц обязаны совпасть с
«Оборотно-сальдовой ведомостью по счёту».

## 5. Прогон сверки — WORK-1540, WORK-1538

1. Скопировать `docs/reconciliation-questions.example.yaml` в рабочий файл.
2. Открыть штатные отчёты 1С из графы `reference_report` и внести числа в
   `expected` — **руками, глядя в отчёт**. Это единственное место, где числа
   берутся не из базы.
3. Прогнать:

```bash
node scripts/reconcile.mjs questions.yaml --out otchet.md
```

Ожидаемое: таблица «вопрос → агент → эталон → расхождение → вердикт» и строка
«сошлось N из 10», меньше чем за 10 минут.

⛔ **Стоп-условие вехи 3:** сверка заняла больше 12 часов → 12 000 ₽ нерентабельны,
объём режется с 10 вопросов до 5.

Заполнить руками раздел «Что мы нашли»: **минимум одна ловушка базы**, иначе
отчёт выглядит формальностью. Кандидаты уже описаны в `note` у вопросов 1, 3, 6,
7, 9 — сработала ли какая-нибудь на этой базе.

Снять 5 скриншотов процесса — они нужны статье (её собственный TODO: на площадке
текст без иллюстраций читают хуже).

**Записать в журнал:** чекбоксы «Образец отчёта сверки создан» и «5 скриншотов сняты».

## Что нельзя делать на чужой базе

- Никаких записей: `ONEC_WRITE_MODE` не выставлять, оставить `off` (значение по умолчанию).
- Данные реального клиента в `tests/fixtures/` не класть даже обезличенными — только демо-база.

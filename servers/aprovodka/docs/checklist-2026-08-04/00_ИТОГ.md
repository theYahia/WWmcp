## 2. Осталось только руками пользователя

### 2.1. npm publish (блокирует MCP Registry и Smithery)

`@theyahia/aprovodka` на npm — **HTTP 404, не опубликован**. Всё остальное в цепочке ждёт этого.

```bash
cd D:/Yahia/active/wwmcps/WWmcp/servers/aprovodka
# ⚠️ сперва проверить: dependencies содержит "@theyahia/mcp-core": "workspace:*",
#    а prepublishOnly делает только build — как резолвится workspace-протокол, НЕ проверено
npm publish --access public --otp=NNNNNN
npm view @theyahia/aprovodka version
```

### 2.2. MCP Registry — публикация + снятие старой записи

```bash
mcp-publisher login github
mcp-publisher publish
curl "https://registry.modelcontextprotocol.io/v0/servers?search=aprovodka"
mcp-publisher status --status deprecated --all-versions -y io.github.theYahia/1c-rest-mcp
# после верификации новой записи:
mcp-publisher status --status deleted --all-versions -y io.github.theYahia/1c-rest-mcp
```

## 3. Осталось незакрытым и почему

| Что | Почему |
|---|---|
| Коллизии товарного знака | Технический гейт: FIPS ищет только по номеру/дате, Rospatent searchplatform отдаёт HTTP 401. Программно невозможно |
| Реестровые номера в реестре Минцифры и записи в реестре ФСТЭК | `reestr.fstec.ru` стабильно роняет WebFetch. «Не найдено поиском» ≠ «нет в реестре» |
| Дословные тексты ПП №1236 / №1937 / ПП 941 и п.29 приказа №239 | Все три вендорских источника вторичные; КонсультантПлюс платный вне бесплатных часов, fstec.ru не отдаётся |
| Стоимость 1С:Совместимо (6000 ₽/год) и цена сертификации (15 000 ₽) | Один вторичный источник / поисковая выдача. Официально не опубликовано → в бюджет не закладывать |
| Принимают ли 1С заявку от ИП/физлица | П.1.12 требует гарантийное письмо «с подписью руководителя и печатью фирмы-разработчика» — написано под юрлицо, применимость к ИП не подтверждена. Аналогично «ИП как правообладатель» в реестре ПО — логически проходит по строке «граждане РФ», дословной нормы никто не читал |
| Трактовка п.7.3 требований 1С для продукта без конфигурации | Единственное место, способное потребовать артефакт внутри конфигурации. Формулировка «в применимой части» не оговорена |
| Квалифицируется ли OData как «штатное документированное средство» по п.7.1 | Слово «OData» в требованиях 1С не встречается ни разу |
| Строгость правоприменения п.2.2.19 Инфостарта на практике | Правило прочитано дословно, поведение модерации — нет |
| Точные формы `Post()` / `Unpost()` / `Balance(Period=,Condition=)` в статье | Сам README пакета помечает их как «валидировать по $metadata своей конфигурации». Живой базы нет |
| ЗУП-пресет: 0 из 18 сущностей verified | Публичных OData-примеров к ЗУП не найдено. Заявлено прямо в `summary` пресета; первые два примера там — `list_entities` для проверки реальных имён |
| MCPB bundle для Smithery | Не собран, отдельная задача |
| Подключение пресетов в `createServer()` | Намеренно не сделано — 2 строки, оставлено на решение (инструмент офлайновый, логично держать всегда включённым) |

## 4. Что сломало исходные посылки задания

1. **«Сертифицированная ФСТЭК российская LLM»** — такого не существует ни у одного вендора; процедуры сертификации ПО с ИИ тоже нет.
2. **«Руководство ≥50 стр. А5» для 1С:Совместимо** — требования нет ни в одном документе 1С.
3. **«npm @theyahia/aprovodka@4.0.0 опубликован»** — на npm HTTP 404.
4. **«Обновить карточку Smithery»** — карточки не существует, это первичная публикация.
5. **«п.1.7 про штатные документированные средства»** — п.1.7 про логотип и наименование; «штатные средства» — это Раздел 7.
6. **«ПП №1236»** — с 01.03.2026 частично перекрыт ПП №1937.

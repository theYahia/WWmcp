# 7.7 Модуль `shortcuts` — 5 инструментов

Модуль включается значением `shortcuts` в `ONEC_SERVICES` и входит в набор по умолчанию. Инструменты модуля — это готовые обёртки над частыми OData-запросами: то же самое достижимо через `odata_query`, но здесь параметры запроса собираются сервером, а не вызывающей стороной.

Имена сущностей в примерах ниже взяты из пресета «1С:Бухгалтерия предприятия 3.0» с пометкой `confidence: verified`. Имена с пометкой `common` — типовые, первоисточником не подтверждённые; перед использованием проверяйте их через `list_entities` или `describe_entity` на своей базе.

## 7.7.1 `find_by_description`

**Назначение.** Найти элементы сущности по подстроке в поле `Description` (наименование). Нечёткий поиск «по названию», когда точный код или `Ref_Key` неизвестен.

| Параметр | Тип | Обяз. | Описание | Пример |
|---|---|---|---|---|
| `entity` | строка | да | Сущность для поиска | `Catalog_Контрагенты` |
| `query` | строка | да | Подстрока для поиска в поле `Description` | `Ромашка` |
| `top` | целое 1–100 | нет, по умолч. 20 | Сколько записей вернуть | `20` |

**Как выполняется.** `$filter=substringof('<query>',Description)` c `$top`. Это синтаксис OData 3.0; функции `contains()` из OData 4.0 платформа не понимает. Одинарная кавычка внутри `query` удваивается автоматически, поэтому наименование вида `ООО "Ромашка'с"` не ломает запрос.

**Возвращает.** Стандартный OData-ответ сущности в JSON: объект с массивом `value`, каждый элемент — запись со всеми полями.

**Пример запроса на естественном языке.** «Найди контрагентов, в названии которых есть Ромашка».

**Примечания и ограничения.**
- Имя сущности передаётся как есть, префикс не достраивается: нужно писать `Catalog_Контрагенты`, а не `Контрагенты`.
- Поиск идёт только по `Description`. У документов наименования нет — их ищут по `get_document_by_number` (номер) либо через `odata_query` по нужному реквизиту.
- Помеченные на удаление записи в выборку попадают: фильтр `DeletionMark eq false` этот инструмент не добавляет.

## 7.7.2 `get_by_key`

**Назначение.** Получить одну запись по её `Ref_Key` — GUID-ссылке, первичному ключу объекта 1С.

| Параметр | Тип | Обяз. | Описание | Пример |
|---|---|---|---|---|
| `entity` | строка | да | Сущность | `Catalog_Номенклатура` |
| `ref_key` | строка (GUID) | да | `Ref_Key` записи | `01234567-89ab-cdef-0123-456789abcdef` |
| `select` | строка | нет | OData `$select` — список возвращаемых полей | `Code,Description` |

**Как выполняется.** Адресация по ключу: `<Сущность>(guid'<ref_key>')`. Значение `ref_key` проверяется на соответствие формату GUID до отправки запроса — некорректное значение даёт ошибку на стороне сервера aprovodka, а не 1С.

**Возвращает.** Одну запись в JSON.

**Пример запроса.** «Покажи карточку номенклатуры по ссылке 01234567-89ab-cdef-0123-456789abcdef».

**Примечания.** Имя сущности не достраивается. Инструмент удобен как второй шаг после `$expand`: вложенные объекты платформа отдаёт, но `$select` по их полям часто возвращает HTTP 400, и отдельный запрос по `Ref_Key` оказывается проще.

## 7.7.3 `count_entities`

**Назначение.** Узнать количество записей сущности, не выгружая их.

| Параметр | Тип | Обяз. | Описание | Пример |
|---|---|---|---|---|
| `entity` | строка | да | Сущность для подсчёта | `Document_РеализацияТоваровУслуг` |
| `filter` | строка | нет | OData `$filter` — условие подсчёта | `Posted eq true` |

**Как выполняется.** `$top=0` вместе с `$inlinecount=allpages`: платформа возвращает только счётчик, без строк.

**Возвращает.** Компактный объект с именем сущности и числом. Пример ответа — иллюстративный, это не вывод реальной базы:

```json
{
  "entity": "Document_РеализацияТоваровУслуг",
  "count": "1842"
}
```

**Примечания.** Если платформа счётчик не вернула, поле `count` будет `null` — тогда объём оценивают постраничной выборкой через `odata_query` с `skip`. Инструмент рассчитан на оценку объёма перед массовой выгрузкой: счёт по всей сущности без фильтра на большой базе всё равно нагружает сервер 1С.

## 7.7.4 `set_deletion_mark`

**Назначение.** Установить или снять пометку удаления (`DeletionMark`) у элемента справочника или документа.

| Параметр | Тип | Обяз. | Описание | Пример |
|---|---|---|---|---|
| `entity` | строка | да | Сущность, `Catalog_*` или `Document_*` | `Document_РеализацияТоваровУслуг` |
| `ref_key` | строка (GUID) | да | `Ref_Key` записи | `01234567-89ab-cdef-0123-456789abcdef` |
| `mark` | логический | нет, по умолч. `true` | `true` — пометить на удаление, `false` — снять пометку | `true` |

**Как выполняется.** OData PATCH по адресу записи с телом `{"DeletionMark": <mark>}`.

**Это пометка, а не удаление.** Запись остаётся в информационной базе со всеми реквизитами и связями; меняется только значение булева поля `DeletionMark`. Из выборок она сама собой не исчезает — чтобы её не видеть, в запросы нужно добавлять `DeletionMark eq false`. Физическое удаление помеченных объектов выполняется отдельно, штатными средствами самой «1С:Предприятия», с контролем ссылочной целостности; порядок этой операции задаётся конфигурацией и настоящим руководством не описывается.

**Отличие от `delete_document`.** `delete_document` выполняет OData DELETE — физическое удаление документа без возможности отмены средствами сервера. `set_deletion_mark` обратим: повторный вызов с `mark: false` возвращает исходное состояние. При включённом гейте записи (`ONEC_WRITE_MODE=preview` или `approval`) переключение пометки распознаётся как структурно обратимая операция и получает токен для `rollback_write`; для физического удаления токен не выдаётся, в ответе указывается причина необратимости.

**Примечания.** Если 1С отказывает в удалении из-за ссылок из других документов, парсер ошибок относит ответ к категории `deletion_locked` и предлагает пометку вместо жёсткого удаления.

## 7.7.5 `get_recent_documents`

**Назначение.** Получить последние документы указанного типа, отсортированные по дате по убыванию.

| Параметр | Тип | Обяз. | Описание | Пример |
|---|---|---|---|---|
| `document_type` | строка | да | Тип документа — с префиксом `Document_` или без него | `РеализацияТоваровУслуг` |
| `top` | целое 1–100 | нет, по умолч. 10 | Сколько последних документов вернуть | `10` |
| `posted_only` | логический | нет, по умолч. `false` | Только проведённые (`Posted eq true`) | `true` |

**Как выполняется.** `$orderby=Date desc` с `$top`; при `posted_only: true` добавляется `$filter=Posted eq true`.

**Пример запроса.** «Покажи десять последних проведённых реализаций».

**Примечания.**
- Это единственный инструмент модуля, который достраивает префикс: обе формы, `РеализацияТоваровУслуг` и `Document_РеализацияТоваровУслуг`, дают один результат.
- Сортировка идёт по полю `Date`, то есть по дате документа, а не по времени его изменения. Для отслеживания правок предназначен `poll_changes_since` из модуля `changes`.
- 1С возвращает время сервера, а не UTC. При сравнении дат с внешними системами учитывайте часовой пояс базы.

# 7.8 Модуль `reports` — 1 инструмент

## 7.8.1 `get_report`

**Назначение.** Получить отчёт по произвольному адресу HTTP-сервиса, опубликованного в вашей конфигурации 1С.

| Параметр | Тип | Обяз. | Описание | Пример |
|---|---|---|---|---|
| `report_url` | строка | да | Полный относительный путь к отчёту | `/hs/reports/balance?date=2024-12-31` |

**Как выполняется.** GET по указанному пути на том же хосте, что задан в `ONEC_BASE_URL`, с теми же учётными данными HTTP Basic и заголовком `Accept: application/json`. Путь передаётся без изменений — сервер aprovodka его не разбирает и не дополняет параметрами.

**Возвращает.** Тело ответа HTTP-сервиса.

**Примечания и ограничения.**
- Это не OData-инструмент. Он обращается к механизму HTTP-сервисов платформы (публикуются отдельно от стандартного интерфейса OData, обычно по префиксу `/hs/`). Если в вашей конфигурации HTTP-сервис отчётов не реализован и не опубликован, вызывать нечего.
- Состав и формат ответа целиком определяются кодом этого HTTP-сервиса. Универсальной схемы нет, поэтому пример ответа в руководстве не приводится: возьмите его из документации на свою конфигурацию.
- Инструмент рассчитан на относительные пути в пределах настроенной базы; произвольные внешние адреса он не обслуживает.

# 7.9 Модуль `odata` — 1 инструмент

## 7.9.1 `odata_query`

**Назначение.** Выполнить произвольный запрос чтения OData 3.0 к любой сущности базы.

| Параметр | Тип | Обяз. | Описание | Пример |
|---|---|---|---|---|
| `entity` | строка | да | OData-сущность | `Catalog_Номенклатура` |
| `filter` | строка | нет | `$filter` | `DeletionMark eq false` |
| `select` | строка | нет | `$select` | `Code,Description` |
| `expand` | строка | нет | `$expand` для связанных таблиц | `Товары` |
| `top` | целое 1–5000 | нет, по умолч. 100 | `$top` | `500` |
| `skip` | целое ≥ 0 | нет, по умолч. 0 | `$skip` | `500` |
| `orderby` | строка | нет | `$orderby` | `Date desc` |
| `inlinecount` | логический | нет, по умолч. `false` | Добавить `$inlinecount=allpages` | `true` |

**Как выполняется.** Собирается один GET-запрос вида `<Сущность>?$format=json&$top=…` с переданными системными параметрами. `$format=json` добавляется всегда.

**Это аварийный выход.** Инструмент существует для запросов, которых нет среди типовых: нестандартная комбинация отборов, редкая сущность, разовая выгрузка. Если для задачи есть специализированный инструмент — пользуйтесь им: он собирает параметры сам и меньше зависит от знания синтаксиса платформы.

**Ограничения, о которых нужно знать заранее.**
- **Имя сущности не достраивается.** Что передали, то и уйдёт в запрос: `Номенклатура` вместо `Catalog_Номенклатура` даст ошибку от 1С, а не автоисправление. Обратная сторона того же свойства полезна: если автодостройка префикса в других инструментах мешает (например, у объекта, чьё имя само начинается с `AccumulationRegister_`), обходным путём служит именно `odata_query`.
- **Виртуальную таблицу регистра вызвать нельзя.** Обращения вида `<Регистр>/Balance(Period=…,Condition=…)` требуют, чтобы символы `/`, `=`, `,`, `:` в пути остались как есть, а здесь имя сущности кодируется целиком. Для остатков и оборотов предназначены отдельные инструменты: `get_accumulation_balance` для регистров накопления и `get_accounting_balance` для регистров бухгалтерии.
- **Только чтение.** Инструмент выполняет GET. Запись идёт через инструменты модулей `catalogs`, `documents`, `registers`, `constants` и `shortcuts` — только так она попадает под гейт записи и аудит.
- Значения параметров передаются в запрос как есть; отвечает за корректность синтаксиса OData вызывающая сторона. Ссылочные поля составного типа (`Recorder`, `ExtDimension*`) фильтруются только через `cast(guid'…','Тип')`.

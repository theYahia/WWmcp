## 11. Приложения

### 11.1 Глоссарий

| Термин | Значение |
|---|---|
| **MCP** (Model Context Protocol) | Протокол, по которому приложение с языковой моделью получает доступ к внешним данным и операциям. Продукт реализует серверную сторону протокола. |
| **MCP-клиент** | Программа пользователя: Claude Desktop, Cursor, Windsurf, VS Code с Copilot и другие. Запускает сервер как процесс (stdio) либо подключается к нему по HTTP. |
| **MCP-сервер** | Процесс, публикующий для клиента набор инструментов и промптов. Представляется именем `aprovodka`. |
| **Инструмент** (tool) | Именованная операция сервера с описанной схемой аргументов; модель вызывает её по имени, результат возвращается текстом. В версии 4.1.0 инструментов 34 (см. 11.2). |
| **Промпт** (prompt) | Готовый многошаговый сценарий, поставляемый с сервером и задающий модели последовательность вызовов инструментов. Их три: `inventory-database`, `find-and-post-document`, `reconcile-balances`. |
| **OData** | Протокол доступа к данным поверх HTTP. «1С:Предприятие» публикует стандартный интерфейс OData версии **3.0**, адрес — `${ONEC_BASE_URL}/odata/standard.odata/`. Версия существенна: подстрока задаётся как `substringof('текст',Description)`, а не `contains()`, даты — литералом `datetime'2026-01-31T00:00:00'`. |
| **EDMX** | XML-документ описания модели данных, который OData отдаёт по запросу `$metadata`: все сущности, их поля и типы. Возвращается инструментом `get_metadata`. |
| **Entity set** (набор сущностей) | Адресуемая коллекция записей одного объекта метаданных. Имя строится из префикса вида объекта и его имени в конфигурации: `Catalog_` — справочники, `Document_` — документы, `InformationRegister_`, `AccumulationRegister_`, `CalculationRegister_`, `AccountingRegister_` — четыре вида регистров. Полный перечень префиксов — в разделе 6.3. |
| **Ref_Key** | GUID ссылки на объект — первичный ключ записи. Аргументы `ref_key` проверяются на формат GUID до отправки запроса в базу. |
| **Проведение** | Операция, формирующая движения документа в регистрах. Выполняется действием OData `Post()` (`post_document`, параметр `operational` — оперативное проведение), отменяется `Unpost()` (`unpost_document`). Признак — поле `Posted`. Непроведённый документ движений не имеет. |
| **Регистр накопления** | Механизм учёта остатков и оборотов, `AccumulationRegister_*`. Итоги дают виртуальные методы `Balance(...)` — остатки на дату, `Turnovers(...)` — обороты за период, `BalanceAndTurnovers(...)`. Инструмент — `get_accumulation_balance`. |
| **Регистр бухгалтерии** | Механизм учёта по плану счетов методом двойной записи, `AccountingRegister_*`. Поля записи: `Period`, `Recorder` (регистратор), `AccountDr_Key` и `AccountCr_Key` (счета дебета и кредита), `Active`, `LineNumber`. Виртуальные таблицы — инструмент `get_accounting_balance`. |
| **Субконто** | Аналитический разрез записи регистра бухгалтерии; в OData — поля `ExtDimension1`…`ExtDimension3`. Тип составной, фильтрация только через `cast(guid'…','Тип')`; прямое сравнение с `guid'…'` даёт пустую выборку либо ошибку. |
| **Табличная часть** | Строки документа или элемента справочника. Адресуется набором сущностей `Document_<Документ>_<ИмяТЧ>` либо навигацией `Document_<Документ>(guid'…')/<ИмяТЧ>`; `get_document_lines` использует второй вариант через `$expand`. Имя зависит от конфигурации — уточняйте по `get_metadata` своей базы. |
| **stdio** | Транспорт, при котором клиент запускает сервер дочерним процессом и обменивается сообщениями через стандартные потоки ввода-вывода. Режим по умолчанию. |
| **Streamable HTTP** | Транспорт для удалённой установки: сервер слушает порт из `HTTP_PORT`. Точки: `POST /mcp` — запросы, `GET /mcp` — поток событий сессии, `DELETE /mcp` — её завершение, `GET /health` — состояние сервера. |

### 11.2 Полная таблица инструментов

Все 34 инструмента версии 4.1.0. Столбец «Тип» показывает, изменяет ли инструмент данные базы. Модуль `meta` регистрируется всегда, остальные включаются переменной `ONEC_SERVICES`.

| Модуль | Инструмент | Назначение | Тип |
|---|---|---|---|
| meta | `get_config_preset` | Описание типовой конфигурации (БП 3.0 / УТ 11 / ЗУП 3.1 / ERP 2): вероятные имена сущностей, примеры, ловушки; офлайн | чтение |
| meta | `list_entities` | Перечень наборов сущностей с фильтром по группе (справочники, документы, регистры, планы, константы, журналы, отчёты) | чтение |
| meta | `get_document_by_number` | Поиск документа по номеру (обёртка над `$filter`) | чтение |
| meta | `get_metadata` | Исходный документ `$metadata` (EDMX/XML) по всей базе | чтение |
| meta | `describe_entity` | Список полей сущности по одной записи-образцу (`$top=1`) | чтение |
| catalogs | `get_catalogs` | Чтение справочников (`$filter`, `$select`, `$orderby`, `$top`, `$skip`) | чтение |
| catalogs | `create_catalog_item` | Создание элемента справочника (OData POST) | запись |
| catalogs | `update_catalog_item` | Изменение элемента справочника по `Ref_Key` (OData PATCH) | запись |
| documents | `get_documents` | Чтение документов с фильтрацией по дате, виду, произвольным полям | чтение |
| documents | `create_document` | Создание документа (OData POST) | запись |
| documents | `update_document` | Изменение документа по `Ref_Key` (OData PATCH) | запись |
| documents | `post_document` | Проведение документа действием `Post()`, в том числе оперативное | запись |
| documents | `unpost_document` | Отмена проведения действием `Unpost()` | запись |
| documents | `delete_document` | Физическое удаление документа (DELETE); безопаснее `set_deletion_mark` | запись |
| documents | `get_document_lines` | Чтение табличной части документа по `Ref_Key` через `$expand` | чтение |
| registers | `get_register` | Чтение записей регистра сведений или регистра накопления | чтение |
| registers | `write_information_register` | Запись в независимый регистр сведений (`InformationRegister_*`) | запись |
| registers | `get_accumulation_balance` | Остатки регистра накопления, метод `Balance(Period=…,Condition=…)` | чтение |
| accounting | `get_accounting_register` | Чтение записей регистра бухгалтерии (проводок) | чтение |
| accounting | `get_accounting_balance` | Виртуальные таблицы регистра бухгалтерии: `Balance`, `Turnovers`, `BalanceAndTurnovers`, `RecordsWithExtDimensions`, `ExtDimensions`. Обороты Дт/Кт не поддержаны — точное имя таблицы источниками не подтверждено | чтение |
| constants | `get_constant` | Чтение значения константы | чтение |
| constants | `set_constant` | Запись значения константы (PATCH поля `Value`) | запись |
| shortcuts | `find_by_description` | Поиск по подстроке наименования (`substringof`) | чтение |
| shortcuts | `get_by_key` | Получение одной записи по `Ref_Key` | чтение |
| shortcuts | `count_entities` | Подсчёт записей сущности, фильтр необязателен | чтение |
| shortcuts | `set_deletion_mark` | Установка или снятие пометки удаления (обратимое мягкое удаление) | запись |
| shortcuts | `get_recent_documents` | Последние документы вида по убыванию даты; можно только проведённые | чтение |
| reports | `get_report` | Отчёт по адресу HTTP-сервиса (`/hs/...`) в пределах `ONEC_BASE_URL` | чтение |
| odata | `odata_query` | Произвольный запрос OData 3.0 к любой сущности | чтение |
| batch | `batch_create_documents` | Параллельное создание 1–100 документов одного вида с отчётом по каждому | запись |
| batch | `batch_update_catalog_items` | Параллельное изменение 1–100 элементов справочников по `Ref_Key` | запись |
| batch | `batch_query` | Параллельное выполнение 1–50 запросов на чтение | чтение |
| changes | `poll_changes_since` | Выборка записей, изменённых после отметки времени; возвращает `next_cursor` | чтение |
| changes | `list_subscriptions` | Указание на отсутствие подписок на события в 1С, перенаправление на опрос | чтение |

Дополнительно, **только при включённом контуре подтверждения записи** (`ONEC_WRITE_MODE` равен `preview` или `approval`), регистрируются ещё два инструмента типа «запись»: `approve_write` — подтверждение одной отложенной операции по её `op_hash` (одноразово, с ограниченным сроком), `rollback_write` — отмена выполненной обратимой операции по токену отката. При значении `off` они отсутствуют.

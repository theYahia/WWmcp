# Руководство пользователя amocrm-mcp

Пакет `@theyahia/amocrm-mcp`, версия 2.0.2, 19 инструментов. Node.js 18 и выше.
API amoCRM версии 4, точка входа `https://<поддомен>.amocrm.ru/api/v4`.

## 1. Что это и кому нужно

Сервер даёт ИИ-агенту доступ к воронке продаж amoCRM: сделки, контакты, компании,
воронки и их этапы, задачи менеджеров, примечания, неразобранное, журнал событий и
сведения об аккаунте. Задача, которую это снимает, — ручная работа в интерфейсе CRM:
«какие сделки висят на этапе „Переговоры“», «заведи контакт и сделку на 150 тысяч»,
«поставь задачу перезвонить завтра в 10», «разбери неразобранное за сегодня».

Кому это нужно: менеджеру по продажам, который ведёт десятки сделок; руководителю
отдела, которому нужен срез по воронке без выгрузки; интегратору, сверяющему данные CRM
с внешней системой.

Ответы приходят форматированным JSON — как их отдал amoCRM, без переупаковки и без
сокращения полей. Это осознанно: структура сущностей amoCRM зависит от настроек аккаунта,
и любая выжимка потеряла бы часть кастомных полей.

## 2. Установка и подключение

### Claude Desktop

Файл `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "amocrm": {
      "command": "npx",
      "args": ["-y", "@theyahia/amocrm-mcp"],
      "env": {
        "AMOCRM_SUBDOMAIN": "mycompany",
        "AMOCRM_ACCESS_TOKEN": "ваш_access_token",
        "AMOCRM_REFRESH_TOKEN": "ваш_refresh_token",
        "AMOCRM_CLIENT_ID": "id_интеграции",
        "AMOCRM_CLIENT_SECRET": "секрет_интеграции"
      }
    }
  }
}
```

Три последние переменные необязательны, но без них сервер не сможет обновить истёкший
токен — см. раздел 6.1. Клиент читает конфигурацию при старте, после правки его нужно
перезапустить.

### Claude Code

```
claude mcp add amocrm -e AMOCRM_SUBDOMAIN=mycompany -e AMOCRM_ACCESS_TOKEN=токен -e AMOCRM_REFRESH_TOKEN=refresh -e AMOCRM_CLIENT_ID=id -e AMOCRM_CLIENT_SECRET=секрет -- npx -y @theyahia/amocrm-mcp
```

### Cursor / Windsurf / VS Code (Copilot)

Cursor и Windsurf принимают тот же блок `mcpServers` в `.cursor/mcp.json` или
`.windsurf/mcp.json`. У VS Code файл `.vscode/mcp.json`, и корневой ключ там — `servers`,
а не `mcpServers`; поля `command`, `args`, `env` те же. Файл рабочей области обычно
попадает в систему контроля версий — токены и секрет интеграции в нём хранить не следует.

### Режим Streamable HTTP

```bash
HTTP_PORT=3000 npx @theyahia/amocrm-mcp --http
```

Режим включается флагом `--http` либо самой переменной `HTTP_PORT` (по умолчанию 3000).
Эндпоинты: `POST /mcp` (запросы; инициализация создаёт сессию), `GET /mcp` (поток SSE
существующей сессии), `DELETE /mcp` (завершение сессии), `GET /health` (`status`,
`server`, `version`, `uptime`, `memory_mb`, `tools`). Сессии различаются заголовком
`mcp-session-id`; кросс-доменные браузерные вызовы по умолчанию запрещены.

Токены берутся из окружения процесса и одни на все сессии: все подключившиеся работают в
amoCRM от имени одной интеграции. Собственной аутентификации у `/mcp` нет — порт в
недоверенной сети не публикуют.

### Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `AMOCRM_SUBDOMAIN` | да | Поддомен: `mycompany` из `mycompany.amocrm.ru`. Хвост `.amocrm.ru` срезается автоматически |
| `AMOCRM_ACCESS_TOKEN` | да | Токен доступа OAuth 2.0, уходит заголовком `Authorization: Bearer …` |
| `AMOCRM_REFRESH_TOKEN` | нет | Токен обновления; включает автоматическое обновление при `401` |
| `AMOCRM_CLIENT_ID` | нет | Идентификатор интеграции, нужен для обновления |
| `AMOCRM_CLIENT_SECRET` | нет | Секрет интеграции, нужен для обновления |
| `AMOCRM_DOMAIN` | нет | Устаревшее имя для `AMOCRM_SUBDOMAIN` |
| `HTTP_PORT` | нет | Порт HTTP-режима; заданная переменная сама включает режим |
| `MCP_DISABLE_SANITIZE` | нет | `true` отключает фильтрацию ответов от инъекций |

Переменные читаются лениво, при первом обращении к API: импорт модуля на отсутствующем
токене не падает, поэтому список инструментов виден и без настроенного доступа.

## 3. Где взять токены доступа

amoCRM использует OAuth 2.0, и «просто ключа API» здесь нет. Порядок такой:

1. Настройки аккаунта → интеграции: `https://<поддомен>.amocrm.ru/settings/widgets/`.
2. Создать новую внешнюю интеграцию.
3. Указать адрес перенаправления. В примерах README это сам адрес аккаунта —
   `https://<поддомен>.amocrm.ru`; сервер использует **то же значение** при обновлении
   токена, поэтому оно должно совпадать.
4. Скопировать **Client ID** и **Client Secret**.
5. Авторизовать интеграцию и получить код авторизации.
6. Обменять код на пару токенов:

```bash
curl -X POST https://<поддомен>.amocrm.ru/oauth2/access_token \
  -H "Content-Type: application/json" \
  -d '{
    "client_id": "…",
    "client_secret": "…",
    "grant_type": "authorization_code",
    "code": "…",
    "redirect_uri": "https://<поддомен>.amocrm.ru"
  }'
```

7. Из ответа взять `access_token` и `refresh_token`.

**Задавайте все пять переменных, а не две.** Токен доступа живёт ограниченное время; при
`401` сервер сам выполнит обновление по `refresh_token`, но только если заданы
`AMOCRM_CLIENT_ID` и `AMOCRM_CLIENT_SECRET`. Без них истёкший токен придётся менять
руками в конфигурации клиента.

**Права интеграции определяют границу возможного.** Инструмент, на который прав нет, не
исчезнет из списка — он вернёт отказ от amoCRM. Ограничивать область работы агента нужно
правами интеграции и пользователя, а не формулировкой запроса.

## 4. Инструменты по задачам

Списочные инструменты работают по схеме `page` (по умолчанию 1) и `limit` (по умолчанию
50). Верхняя граница `limit` — 250, кроме `list_events`, где она равна 100.

Многие читающие инструменты принимают массив `with` — какие связанные сущности вложить в
ответ. Это дешевле, чем второй запрос, но заметно увеличивает объём.

### 4.1 Сначала — структура воронки

**`list_pipelines`** — все воронки продаж с их этапами (статусами). Параметров нет.
Возвращает идентификаторы воронок и статусов — именно их принимают `list_leads`,
`create_lead`, `update_lead` и `accept_unsorted`.

Вызывать этот инструмент нужно **до** любой работы со сделками: названия этапов на экране
и их числовые идентификаторы — разные вещи, а идентификаторы у каждого аккаунта свои.

**`get_account`** — сведения об аккаунте: название, тариф, пользователи, типы задач.
Необязательный массив `with` принимает `amojo_id`, `amojo_rights`, `users_groups`,
`task_types`, `version`, `datetime_settings`. Через `task_types` узнают допустимые
значения `task_type_id`, через `users_groups` — идентификаторы сотрудников.

### 4.2 Сделки

**`list_leads`** — поиск и выборка. Все параметры необязательны: `query`
(полнотекстовый поиск по названию сделки, контактам и компаниям), `page`, `limit`
(до 250), `pipeline_id`, `statuses` — массив пар `{pipeline_id, status_id}`, и `with`
(`contacts`, `loss_reason`, `catalog_elements`, `is_price_modified_by_robot`,
`source_id`).

**`get_lead`** — одна сделка по `lead_id`; `with` принимает `contacts`,
`catalog_elements`, `loss_reason`, `source_id`.

**`create_lead`** — обязателен `name`. Необязательны `price`, `pipeline_id`,
`status_id`, `responsible_user_id` и `custom_fields_values` — массив объектов
`{field_id, values: [{value}]}`.

**`update_lead`** — обязателен `lead_id`; остальные поля те же и все необязательны.
Отправляются только переданные. Смена этапа делается именно здесь: `status_id`
(и `pipeline_id`, если сделка переезжает в другую воронку).

### 4.3 Контакты и компании

**`list_contacts`** — `query` ищет по имени, телефону и почте одновременно; `page`,
`limit` (до 250), `with` (`leads`, `customers`, `catalog_elements`).

**`get_contact`** — по `contact_id`, с тем же `with`.

**`create_contact`** — все поля необязательны: `name` (полное имя), `first_name`,
`last_name`, `responsible_user_id`, `custom_fields_values`. Телефон и почта в amoCRM —
это **кастомные поля**, а не отдельные параметры: их задают через
`custom_fields_values` с идентификаторами полей аккаунта.

**`list_companies`** — `query` по названию, `page`, `limit` (до 250), `with` (`leads`,
`contacts`, `catalog_elements`).

**`create_company`** — обязателен `name`; необязательны `responsible_user_id` и
`custom_fields_values` (адрес, сайт и прочее).

### 4.4 Задачи менеджеров

**`list_tasks`** — фильтры `entity_type` (`leads`, `contacts`, `companies`), `entity_id`
(требует `entity_type`), `is_completed`, `responsible_user_id`, плюс `page` и `limit`.

**`create_task`** — обязательны `text`, `entity_id`, `entity_type` и `complete_till` —
срок **числом, временной меткой Unix** (секунды), а не строкой даты. Необязательны
`task_type_id` (1 — звонок, 2 — встреча, 3 — письмо; полный список — через `get_account`
с `with: ["task_types"]`) и `responsible_user_id`.

**`complete_task`** — обязательны `task_id` и `result_text`. Ставит признак выполнения и
записывает результат, который появится в ленте связанной сущности.

### 4.5 Неразобранное

**`list_unsorted`** — входящие заявки из форм, разбора почты и прочих источников,
которые ещё не приняты в воронку. Фильтры: `pipeline_id`, `page`, `limit`.

**`accept_unsorted`** — принятие заявки: обязателен `uid` (строковый идентификатор из
списка, **не** числовой), необязательны `pipeline_id`, `status_id`, `user_id`. После
принятия заявка становится обычной сделкой.

### 4.6 Примечания, поиск, журнал

**`add_note`** — примечание к сущности. Обязательны `entity_id`, `entity_type` (`leads`,
`contacts`, `companies`) и `text`; необязательный `note_type` — `common` (по умолчанию),
`call_in`, `call_out`, `service_message`.

**`search`** — универсальный поиск по сделкам, контактам и компаниям сразу. Обязателен
`query` **не короче трёх символов** (проверяется до обращения к API); необязателен
`limit` (до 250).

**`list_events`** — журнал действий: смены статусов, звонки, примечания. Фильтры:
`entity` (`lead`, `contact`, `company`, `task`, `customer`), `entity_id`, `type` (строка
вида `lead_status_changed`, `incoming_call`, `entity_linked`), `page`, `limit` (до 100).

## 5. Готовые сценарии

**1. «Покажи сделки на этапе „Переговоры“ вместе с контактами.»**
`list_pipelines` (найти `pipeline_id` и `status_id` нужного этапа) → `list_leads`
(`statuses: [{pipeline_id, status_id}]`, `with: ["contacts"]`). Фильтровать по названию
этапа нельзя — только по числовым идентификаторам.

**2. «Заведи клиента: контакт, компанию и сделку на 150 000.»**
`create_contact` (`name`, `custom_fields_values` с телефоном) → `create_company`
(`name`) → `list_pipelines` (взять воронку и первый этап) → `create_lead` (`name`,
`price: 150000`, `pipeline_id`, `status_id`). Идентификаторы кастомных полей телефона и
почты — из настроек аккаунта.

**3. «Перенеси сделку 12345 на этап „Счёт выставлен“.»**
`list_pipelines` (найти `status_id`) → `update_lead` (`lead_id: 12345`, `status_id`).
Проверить — `get_lead`.

**4. «Поставь задачу перезвонить по сделке 12345 завтра в 10:00.»**
`create_task` (`text`, `entity_type: "leads"`, `entity_id: 12345`, `complete_till` —
метка Unix для завтрашних 10:00, `task_type_id: 1`). Дату нужно перевести в число
секунд: строку даты API не примет.

**5. «Что не сделано у Иванова?»**
`get_account` (`with: ["users_groups"]`, найти идентификатор сотрудника) →
`list_tasks` (`responsible_user_id`, `is_completed: false`).

**6. «Разбери неразобранное: прими заявки в основную воронку.»**
`list_unsorted` (`limit: 50`) → по каждой заявке `accept_unsorted` (`uid` из списка,
`pipeline_id`, `status_id`, `user_id`). Обратите внимание: ключ здесь строковый `uid`, а
не числовой идентификатор сделки.

**7. «Найди всё по слову „Ромашка“.»**
`search` (`query: "Ромашка"`). Один вызов охватывает сделки, контакты и компании.
Запрос короче трёх символов будет отклонён до обращения к API.

**8. «Что происходило со сделкой 12345 за последнее время?»**
`list_events` (`entity: "lead"`, `entity_id: 12345`, `limit: 100`). Для сужения — фильтр
`type`, например `lead_status_changed`.

**9. «Запиши в карточку итог разговора.»**
`add_note` (`entity_type: "leads"`, `entity_id`, `note_type: "call_out"`, `text`).
Примечание появится в ленте сделки.

## 6. Ограничения и подводные камни

### 6.1 Токен обновляется сам, но только в текущем процессе

При `401` общий HTTP-клиент сбрасывает токен и повторяет запрос; следующая попытка
запускает обмен `refresh_token` на новую пару. Работает это лишь при заданных
`AMOCRM_REFRESH_TOKEN`, `AMOCRM_CLIENT_ID` и `AMOCRM_CLIENT_SECRET` — иначе приходит
явное сообщение, что автоматическое обновление не настроено.

Две особенности:

- **amoCRM меняет токен обновления при каждом использовании.** Сервер сохраняет новую
  пару в переменные окружения **своего процесса**. При перезапуске значения берутся из
  конфигурации клиента заново, и если там лежит уже израсходованный `refresh_token`,
  обновление не пройдёт. Для долгоживущей установки токены хранят снаружи и обновляют в
  конфигурации.
- Одновременные обновления объединяются в одно: второй параллельный обмен предъявил бы
  уже израсходованный токен.

### 6.2 Ограничитель частоты — 7 запросов в секунду

Клиент несёт встроенное ограничение по схеме «маркерное ведро»: 7 запросов в секунду,
пополнение раз в секунду. Это соответствует документированному лимиту amoCRM на аккаунт.
Ограничение работает всегда и не отключается; при превышении вызов не отклоняется, а
ждёт своей очереди. Практическое следствие: выгрузка из десятков страниц идёт заметно
медленнее, чем «сколько успеем».

### 6.3 Изменяющие операции не повторяются автоматически

Повтор выполняется только для запросов чтения. Все создания и изменения
(`create_lead`, `update_lead`, `create_contact`, `create_company`, `create_task`,
`complete_task`, `add_note`, `accept_unsorted`) уходят методами POST и PATCH и при
таймауте, `5xx` или обрыве связи **не повторяются** — к тексту ошибки дописывается
предупреждение проверить, не создан ли объект.

Повторов чтения не больше трёх, задержка `1000 × 2^(попытка−1)` мс, но не дольше
8 секунд. Таймаут одного запроса — 15 секунд, переменной окружения не настраивается.

Практический вывод: получив ошибку на `create_lead`, сначала проверьте `search` или
`list_leads`, и только потом повторяйте.

### 6.4 Ответ отдаётся целиком

Инструменты возвращают форматированный JSON ответа amoCRM без сокращения полей. Сделка со
всеми кастомными полями — объёмный документ; `list_leads` с `limit: 250` и
`with: ["contacts"]` даёт очень большой ответ.

Ответ длиннее 50 000 символов обрезается с пометкой о срезке. Практика: держать `limit` в
пределах 20–50, добавлять `with` только когда связанные сущности действительно нужны, и
листать `page`.

Тексты из ответов (названия, примечания, комментарии) проходят фильтр: конструкции вида
«игнорируй предыдущие инструкции» и теги `<system>` заменяются на `[filtered]`.
Отключается переменной `MCP_DISABLE_SANITIZE=true`.

### 6.5 Пустой ответ приходит как пустой объект

На пустой выборке amoCRM отвечает `204 No Content`. Сервер превращает это в пустой объект
`{}`, а не в ошибку. Пустой ответ означает «совпадений нет», а не «инструмент не
сработал».

### 6.6 Телефон и почта — кастомные поля

У контактов и компаний нет отдельных параметров телефона, почты, сайта и адреса. Всё это
живёт в `custom_fields_values` — массиве объектов `{field_id, values: [{value}]}`, где
`field_id` — идентификатор поля **вашего** аккаунта. Инструмента получения списка
кастомных полей в сервере нет: идентификаторы берут из настроек amoCRM либо из ответа
`get_contact` по уже существующей карточке, где они видны рядом со значениями.

### 6.7 Что здесь нельзя

Набор инструментов покрывает создание и правку, но не удаление: инструментов удаления
сделок, контактов, компаний, задач и примечаний в сервере нет вовсе. Нет также
изменения контактов и компаний — только создание (`create_contact`, `create_company`);
править существующие карточки придётся в интерфейсе. Обновление доступно только у сделок
(`update_lead`) и задач (`complete_task`).

### 6.8 Форматы

| Что | Формат |
|---|---|
| Срок задачи `complete_till` | Целое число — временная метка Unix в секундах |
| `pipeline_id`, `status_id`, `responsible_user_id`, `entity_id` | Целые числа из `list_pipelines` / `get_account` |
| `uid` в `accept_unsorted` | Строка |
| `query` в `search` | Не короче трёх символов |
| `limit` | До 250; у `list_events` — до 100 |
| Кастомные поля | `[{field_id, values: [{value}]}]` |

## 7. Частые ошибки

| Что видно | Что это значит | Что делать |
|---|---|---|
| `AMOCRM_SUBDOMAIN is not set` | Поддомен не дошёл до процесса; проявляется при первом обращении к API | Задать `AMOCRM_SUBDOMAIN` (только поддомен) в блоке `env` и перезапустить клиент |
| `AMOCRM_ACCESS_TOKEN is not set` | Нет токена доступа | Пройти обмен кода на токены (раздел 3) |
| `Токен amoCRM истёк (401), а авто-обновление не настроено…` | Токен просрочен, а `AMOCRM_REFRESH_TOKEN` / `AMOCRM_CLIENT_ID` / `AMOCRM_CLIENT_SECRET` не заданы | Добавить три переменные либо обновить `AMOCRM_ACCESS_TOKEN` вручную |
| `Не удалось обновить токен amoCRM (HTTP 400/401)…` | Обмен не прошёл: неверные идентификатор или секрет интеграции, либо `refresh_token` уже израсходован | Сверить `AMOCRM_CLIENT_ID` и `AMOCRM_CLIENT_SECRET`; получить свежую пару токенов заново |
| `Отказ в доступе (HTTP 403)` | Токен верен, но интеграции не выданы права на этот раздел | Настроить права интеграции в настройках аккаунта |
| `Ресурс не найден` (HTTP 404) | Нет объекта с таким идентификатором либо неверный поддомен | Проверить идентификатор через `search` / `list_leads`; проверить `AMOCRM_SUBDOMAIN` |
| HTTP 400 при создании сделки или контакта | amoCRM отверг тело: неверный `status_id` для воронки, несуществующий `field_id`, не тот тип значения | Сверить идентификаторы через `list_pipelines` и `get_account`; кастомные поля — по идентификаторам своего аккаунта |
| HTTP 400 при `create_task` | `complete_till` передан строкой даты вместо числа | Перевести срок во временную метку Unix (секунды) |
| `Ошибка валидации: query: …` | Проверка параметров: запрос `search` короче трёх символов | Удлинить запрос |
| `Rate limit. Повторите через Nс` (HTTP 429) | Лимит amoCRM выбран, несмотря на встроенное ограничение 7 запросов в секунду | Пауза; уменьшить `limit`, убрать лишние `with`, разнести выгрузку |
| `Таймаут запроса` | Ответ не пришёл за 15 секунд | Для чтения — повторить с меньшим `limit`; для записи — сначала проверить, не создан ли объект |
| `Повтор не выполнен автоматически, потому что операция изменяет данные…` | Сбой на записи, результат неизвестен | Раздел 6.3: проверить `list_leads` / `list_tasks`, потом повторять |
| Пустой объект `{}` в ответе | amoCRM ответил `204`: совпадений нет | Ослабить фильтры; проверить, что `entity_id` и `entity_type` заданы вместе |
| Ответ обрезан с пометкой `[Truncated…]` | Выдача длиннее 50 000 символов | Уменьшить `limit`, убрать `with`, листать `page` |

Журнал сервера идёт в **stderr** — stdout занят протоколом JSON-RPC. Туда же пишется
строка `Access token refreshed` при успешном обновлении токена и предупреждения о
повторах.

# /task-status — Статус и обсуждение задачи

## Алгоритм

1. `get_task` (taskId, fields) — текущее состояние: название, статус, исполнитель, проект.
2. Узнай, какие статусы допустимы. Наборы статусов в Planfix хранятся как справочники:
   - `list_directories` (offset, pageSize, fields) — найди справочник статусов;
   - `list_directory_entries` (directoryId, offset, pageSize) — его записи, из них берётся числовой ID статуса.
3. Покажи пользователю текущий статус и допустимые варианты. **Не подставляй ID статуса наугад** — `update_task` принимает число, а не название.
4. `update_task` (taskId, name, description, status, assigneeId) — примени изменение. Передавай только те поля, которые реально меняются.
5. Прочитай переписку: `get_comments` (taskId, offset, pageSize, fields) — что обсуждалось, кто последний писал, есть ли блокер.
6. Зафиксируй решение: `add_comment` (taskId, body).
7. Перечитай `get_task` и покажи «было → стало».

## Важно

- Смена исполнителя — это тоже `update_task` (assigneeId); ID сотрудника берётся из `list_users`, а не из имени.
- Массовой смены статуса нет: один вызов `update_task` на задачу. Пачку правок сначала покажи списком и подтверди.
- Если нужного статуса нет в справочнике — статус в этой конфигурации Planfix не заведён; сообщи об этом, не подбирай похожий.

## Формат ответа

```
## Задача 15420

**Название**: Подготовить отчёт по Q3
**Статус**: В работе → Выполнена
**Исполнитель**: Иванов И.

### Последние комментарии
1. 2026-09-01 — Иванов И. — «Черновик готов, жду цифры от финансов»
2. 2026-09-02 — Петров П. — «Цифры отправил»

Добавлен комментарий: «Закрываю, отчёт принят».
```

## Примеры

```
/task-status 15420
/task-status 15420 выполнена
/task-status 15420 покажи комментарии
```

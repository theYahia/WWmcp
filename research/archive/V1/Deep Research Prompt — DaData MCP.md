## ЧАСТЬ 1: DaData API — полная карта возможностей

### 1.1 Полный каталог endpoint'ов
Составь исчерпывающий список ВСЕХ публичных endpoint'ов DaData API, не только основных. Включи:
- Suggestions API: address, party, bank, fio, email, fms_unit, country, currency, okved2, okpd2
- Cleaner API: address, phone, email, name, passport, birthdate
- findById: party (по ИНН), bank (по БИК), address (по ФИАС), fms_unit (по коду)
- Geolocate: address (обратное геокодирование)
- Справочники и вспомогательные endpoints

Для каждого endpoint укажи:
- Точный URL
- HTTP метод
- Формат запроса (JSON schema)
- Формат ответа (ключевые поля)
- Какой API (Suggestions или Cleaner)
- Бесплатный или платный
- Rate limit

### 1.2 Неочевидные возможности
- Какие endpoint'ы малоизвестны но полезны? (например, поиск банка по БИК, подсказки ФИО)
- Какие фильтры и параметры часто упускают? (locations_boost, from_bound/to_bound, div)
- Есть ли недокументированные или бета-endpoint'ы?
- Какие комбинации endpoint'ов дают синергию? (например, suggest_address → geocode → reverse_geocode для валидации)

### 1.3 Ограничения и подводные камни
- Точные rate limits по каждому API (req/s, req/day, connections/min)
- Что происходит при превышении лимитов? (HTTP коды, retry headers)
- Какие данные доступны только на платных тарифах? (founders, licenses, finance details)
- Разница между тарифами: Бесплатный / Стандарт / Стандарт+ / Максимальный
- Известные баги или inconsistencies в API
- Как API ведёт себя с невалидными данными? (пустая строка, мусор, иностранные адреса)

## ЧАСТЬ 3: Архитектурные решения

### 3.1 Какие tools делать?
Предложи оптимальный набор MCP tools. Для каждого:
- Название (snake_case, понятное AI-агенту)
- Описание на английском (как его увидит Claude/GPT)
- Input schema (Zod)
- Output format
- Почему этот tool нужен (реальный use case)
- Приоритет: must-have / nice-to-have / v2

Думай не только об обёртках над endpoint'ами, но и о **композитных tools**:
- `enrich_lead` — по неполным данным (имя + телефон) достать всё: компанию, адрес, email, реквизиты
- `validate_counterparty` — проверить контрагента по ИНН: статус, адрес, руководитель, финансы, ОКВЭД
- `batch_validate_phones` — массовая валидация списка телефонов
- `smart_address_resolve` — цепочка: подсказка → стандартизация → геокодирование

### 3.2 Resources и Prompts
MCP поддерживает не только tools, но и:
- **Resources** — статические данные для контекста (справочник ОКВЭД? список регионов?)
- **Prompts** — шаблоны промтов для типовых задач ("проверь контрагента", "очисти базу телефонов")

Какие resources и prompts стоит добавить для DaData MCP?

### 3.3 Формат ответов
AI-агенты лучше работают с определённым форматом. Исследуй:
- Как лучше форматировать ответ tool? (чистый JSON, markdown, гибрид?)
- Нужно ли добавлять "пояснения" к данным? (например, qc=0 → "Адрес распознан уверенно")
- Как обрабатывать пустые результаты? (0 suggestions)
- Как обрабатывать частичные результаты? (адрес распознан до города, но не до дома)

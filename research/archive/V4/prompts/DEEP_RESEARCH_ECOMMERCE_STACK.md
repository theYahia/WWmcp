# Deep Research — E-commerce тройка: Ozon + Wildberries + Yandex Market + МойСклад + СДЭК + DaData + ЮKassa

## Контекст

Мы — @theyahia (npm org, GitHub: github.com/theYahia). У нас уже есть **реальные MCP-серверы** (с кодом) для всех 7 сервисов в этом стеке:
- `@theyahia/ozon-mcp`
- `@theyahia/wildberries-mcp`
- `@theyahia/yandex-market-mcp`
- `@theyahia/moysklad-mcp`
- `@theyahia/cdek-mcp`
- `@metarebalance/dadata-mcp` (31 tool, v1.0.4)
- `@theyahia/yookassa-mcp`

Идея: объединить эти 7 MCP-серверов в **единый e-commerce стек**, где МойСклад — центральная ERP (единая правда о складе), маркетплейсы — каналы продаж, СДЭК — логистика, DaData — валидация адресов, ЮKassa — оплата на собственном сайте. Это позиционируется как **"первый в мире MCP e-commerce стек для российского рынка"**.

**Цель исследования:** Понять, насколько это реально технически, какие подводные камни, что нужно доработать в существующих серверах, и стоит ли это делать вообще — или это маркетинговый пузырь.

## Блок 1: Архитектура единого стека — как это должно работать

### Теоретическая схема

```
МойСклад (ERP, единая правда о складе)
    ↕ синхронизация
    ├── Ozon Seller API (товары, заказы, цены, остатки)
    ├── Wildberries API (товары, заказы, цены, остатки)
    └── Yandex Market API (товары, заказы, цены, остатки)

Новый заказ с маркетплейса:
    → МойСклад (обновить остатки)
    → СДЭК (создать накладную)
    → DaData (валидировать адрес доставки)

Заказ с собственного сайта:
    → ЮKassa (принять оплату)
    → МойСклад (создать заказ)
    → СДЭК (создать доставку)
```

### Вопросы для исследования

1. **Существуют ли коммерческие аналоги этого стека?**
   - ApiMonster, Альбато, плагины МойСклад «3-в-1» — что они делают?
   - RetailCRM как альтернативный центр стека?
   - Какие SaaS-решения уже объединяют Ozon+WB+YM?
   - Сколько они стоят? (₽/мес)
   - Чем MCP-версия лучше/хуже?

2. **Как реально работает синхронизация МойСклад ↔ маркетплейсы?**
   - Каким способом продавцы сейчас синхронизируют остатки?
   - Через API МойСклад или через маркетплейс API?
   - Интервал синхронизации: real-time или по расписанию?
   - Что происходит при конфликте (продали на двух площадках одновременно)?

3. **Нужен ли центральный оркестратор?**
   - MCP-серверы работают независимо — каждый отдельный сервер
   - Как AI-агент (Claude) будет координировать работу 7 серверов одновременно?
   - Ограничения: сколько MCP-серверов Claude может использовать в одном сеансе?

## Блок 7: Технические вызовы — подводные камни

### 1. Маппинг товаров между площадками
- Одинаковый товар имеет разные ID на каждой площадке
- Артикул (offer_id/article) — единственный общий ключ?
- Категории: каждый маркетплейс имеет свою структуру
- Фото, описания — разные требования
- **Вопрос: как AI-агент будет понимать, что товар на Ozon = товар на WB?**

### 2. Синхронизация остатков (самая сложная часть)
- Race condition: продали последний товар на двух площадках одновременно
- Задержка обновления: Ozon применяет изменения не мгновенно
- МойСклад как source of truth — но заказ приходит с маркетплейса
- Порядок: заказ на Ozon → обновить МойСклад → обновить WB и YM остатки
- Как это сделать через MCP? AI-агент должен выполнить 4 вызова последовательно
- **Вопрос: может ли Claude надёжно выполнять цепочки из 10+ tool calls?**

### 3. Rate limits конфликт
- МойСклад: 45 req/3 сек = 15 req/сек
- WB: 300 req/мин = 5 req/сек (с учётом штрафов реально 2-3)
- Ozon: 100 req/мин на метод
- При синхронизации 1000 товаров на 3 площадки: сколько запросов?
- Сколько времени займёт полная синхронизация?

### 4. Форматы данных
- МойСклад: цены в копейках (integer)
- Ozon: цены в строках ("1500.00")
- WB: цены в ?
- YM: цены в ?
- Вес: граммы vs килограммы vs ?
- Размеры: см vs мм vs ?
- **Нужна ли прослойка конвертации?**

### 5. Ошибки и восстановление
- Что если один API упал, а остальные работают?
- Partial failure: обновили Ozon, но WB вернул ошибку
- Как откатить? Или повторить?
- Логирование и мониторинг

### 6. MCP ограничения
- Каждый MCP-сервер — отдельный процесс
- Claude подключается к каждому отдельно
- Нет общего состояния между серверами
- Нет транзакций (atomicity)
- **Вопрос: это фундаментальное ограничение или решаемо?**

## Блок 9: Реалистичная оценка — стоит ли делать

### Аргументы ЗА
- Первый в мире MCP e-commerce стек
- Маркетинговая ценность (killer feature для статей, запусков)
- Все 7 серверов уже существуют
- Синергия: каждый сервер продвигает остальные
- Потенциал для консалтинга (100-500K₽ за настройку)

### Аргументы ПРОТИВ
- AI-агент не может работать по расписанию (нет cron)
- Нет гарантии atomicity между 7 серверами
- Race conditions при синхронизации остатков
- Реальные продавцы используют SaaS с UI, не CLI
- MCP не поддерживает webhooks (push-уведомления)
- Rate limits делают массовую синхронизацию медленной

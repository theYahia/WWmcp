# Deep Research — Партнёрские и реферальные программы российских сервисов для MCP-серверов

## Контекст

Мы — @theyahia (npm org, GitHub: github.com/theYahia). Создали **47 MCP-серверов** (Model Context Protocol) для российских API. Все 47 имеют реальный код, опубликованы на npm и GitHub. Каждый MCP-сервер — это open-source инструмент, который позволяет пользователям Claude, Cursor, VS Code, Windsurf работать с российскими API через AI.

**Модель монетизации:** В README каждого MCP-сервера мы размещаем реферальную ссылку на регистрацию в сервисе. Когда пользователь MCP ещё не подключён к сервису — он переходит по ссылке, регистрируется, мы получаем комиссию. Это нативная монетизация: пользователь всё равно должен получить API-ключ, мы просто направляем его через нашу реферальную ссылку.

**Текущий статус:**
- ИП зарегистрировано
- Расчётный счёт: **нужно открыть** (Тинькофф / Точка / Модуль)
- Ни в одной реферальной программе ещё не зарегистрированы
- У нас уже есть MCP-серверы для всех сервисов ниже

**Предварительные данные из V3:**

|--------|--------------------------|
| amoCRM | до 50% от лицензий |

Нужно **верифицировать** и **расширить** эти данные, а также найти программы для всех остальных сервисов из нашей серии.

## Блок 1: Верификация существующих программ

Для каждого из 13 сервисов выше проверить АКТУАЛЬНЫЕ условия на 2026 год:

1. **Точная ссылка** на страницу партнёрской/реферальной программы
2. **Тип программы:** реферальная (просто ссылка) vs партнёрская (нужна сертификация) vs агентская (нужен договор)

   - Сколько времени занимает одобрение?
7. **Формат реферальной ссылки** — как выглядит, можно ли кастомизировать
8. **Отслеживание конверсий** — есть ли личный кабинет, API для трекинга
9. **Способ выплат** — на р/с, на карту, ЮMoney, другое
10. **Ограничения** — запрет на контекстную рекламу, ограничения на бренд

## Блок 3: Как именно нам встраивать реферальные ссылки

Для каждой подтверждённой программы — конкретный план интеграции в наш MCP:

1. **Где размещать ссылку в README:**
   - В разделе "Получение API-ключа" (самое нативное место)
   - В разделе "Установка" (при конфигурации env vars)
   - Отдельный раздел "Партнёрская программа"
   - Какой формат лучше: просто ссылка, баннер, callout?

2. **Формулировка** — как написать, чтобы:
   - Было полезно (не выглядело как реклама)
   - Соответствовало правилам программы
   - Конвертировало (лучшие практики affiliate в open-source)

3. **Юридические тонкости:**
   - Нужно ли раскрывать что это реферальная ссылка? (FTC disclosure, российское законодательство)
   - Ограничения на использование в open-source проектах
   - Могут ли npm/GitHub заблокировать за реферальные ссылки?

## Формат ответа

Для каждой партнёрской программы:
1. **Сервис и URL** — точная ссылка на страницу программы
2. **Тип:** реферальная / партнёрская / агентская
3. **Комиссия:** точный процент и модель (разовая/recurring/lifetime)
4. **Требования:** ИП? р/с? сертификация? сроки?
5. **Минимальный порог выплат**
6. **Способ выплат**
7. **Наш MCP-сервер:** какой из 47 серверов подключить
8. **Оценка дохода:** при 100 / 500 / 2000 пользователях
9. **Приоритет:** немедленно / после р/с / после сертификации
10. **Конкретный следующий шаг** — что именно сделать прямо сейчас

Не давай абстрактных советов. Нужны конкретные URL, конкретные цифры, конкретные шаги. Если информация о программе не найдена — явно указать "не найдено" и предложить альтернативу (написать в поддержку, найти через партнёрскую сеть).

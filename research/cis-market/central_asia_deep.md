# Central Asia API verification and MCP implementation guide

**Only 17 of 40 investigated services have usable public APIs, and just 4 already have MCP servers.** This creates a significant greenfield opportunity across Kazakhstan and Uzbekistan's most critical digital infrastructure — payments, e-invoicing, and marketplace integrations. The biggest surprise: Kaspi.kz, the region's dominant super-app, has no official payment API, while Forte Bank offers the best-documented API in the entire region. Across Kyrgyzstan and Tajikistan, the developer ecosystem is almost nonexistent, with closed mobile-app-first platforms dominating both markets.

## KAZAKHSTAN — Finance and super-apps

### 1. Kaspi.kz (Kazakhstan)
- **Developer Portal**: https://guide.kaspi.kz/partner/ru/shop/api/general (Russian guide); Confluence-style docs at kaspi.kz/merchantcabinet/support/
- **API Status**: Active (Marketplace Seller API only)
- **Base URL**: `https://kaspi.kz/shop/api/v2`
- **Auth**: Static API Token (`X-Auth-Token` header), generated by company director in seller cabinet
- **Key Endpoints**: `GET /v2/orders` (list/filter orders), `POST /v2/orders` (update status), `GET /v2/orderentries/{id}` (line items), `GET /v2/pointsofsale/{id}` (warehouse info), `GET /v2/cities`, `GET /v2/merchantreviews`, Content API: `GET /api/products/categories`, `POST /api/products` (create product)
- **Rate Limits**: Not documented
- **Sandbox**: No
- **Official SDK**: None (community Go library: `abdymazhit/kaspi-merchant-api`)
- **Existing MCP**: **None found**
- **Webhooks**: Not natively supported. Third-party ApiMonster.io provides polling connectors
- **Docs Quality**: 3/5 — Russian primary, English available; fragmented across subdomains; no OpenAPI spec
- **Est. MCP Build**: M
- **Notes**: **Kaspi Pay has NO official public API** — only third-party wrappers (ApiPay.kz, AiPay.kz). Delivery API is embedded in order management. Requires registered Kaspi merchant (ИП or ТОО). Director-level access needed for token generation. JSON:API spec compliant.

### 2. Halyk Bank / ePay (Kazakhstan)
- **Developer Portal**: https://epayment.kz/en-US/docs/mobile_sdk_documentation
- **API Status**: Active — **#1 payment gateway in Kazakhstan** (~65% of online shops)
- **Base URL**: `https://epay.halykbank.kz`
- **Auth**: OAuth2-style (TerminalID + ClientID + ClientSecret → token)
- **Key Endpoints**: Payment widget, API-based cryptogram payments, P2P transfers, invoice link generation, Apple Pay/Google Pay/Halyk QR by API, transaction confirm/cancel/refund, saved cards management
- **Rate Limits**: Not documented
- **Sandbox**: **Yes** — test credentials at epayment.kz/en-US/docs/Test%20credentials
- **Official SDK**: iOS SDK, Android SDK
- **Existing MCP**: **None found** (community: PHP/Laravel packages for ePay)
- **Webhooks**: Yes — payment status notifications
- **Docs Quality**: 4/5 — Full English, Russian, Kazakh; well-structured navigation
- **Est. MCP Build**: M
- **Notes**: Юрлицо required. Supports Visa, MasterCard, UnionPay, AmEx, JCB, Apple/Google/Samsung Pay, Halyk QR. Legacy domain `epay.kkb.kz` still active.

### 3. Forte Bank (Kazakhstan)
- **Developer Portal**: https://docs.fortebank.com/en/ — **Best-documented API in the region**
- **API Status**: Active (API v3, since September 2022)
- **Base URL**: `https://gateway.fortebank.com/`
- **Auth**: HTTP Basic (Shop ID + Secret Key)
- **Key Endpoints**: `POST /transactions/payments` (one-step), `POST /transactions/authorizations` (two-step hold), `POST /transactions/captures`, `POST /transactions/voids`, `POST /transactions/refunds`, `POST /transactions/payouts`, `POST /transactions/tokenizations`, `POST /transactions/p2p`, `GET /transactions/{uid}` (status), Pay by Link, Subscription service
- **Rate Limits**: HTTP 429 documented; exponential backoff recommended
- **Sandbox**: **Yes** — full test mode with test card data, Postman collection provided
- **Official SDK**: iOS/Android (via begateway GitHub)
- **Existing MCP**: **None found**
- **Webhooks**: Yes — transaction status notifications
- **Docs Quality**: **5/5** — Outstanding. Full English, MkDocs-based, Postman collections, error codes, changelog
- **Est. MCP Build**: **S**
- **Notes**: Built on beGateway/eComCharge platform. `X-API-Version: 3` header required. Host-to-host raw card requests need special permissions. Do NOT confuse with forte.net (US company).

## Three critical patterns shaping the implementation roadmap

**Central Asia's API landscape splits into two tiers.** Kazakhstan and Uzbekistan have a functional developer ecosystem with **17 services offering real, documented APIs** — concentrated in payments, logistics, and mandatory fiscal compliance. Kyrgyzstan and Tajikistan remain almost entirely closed, with mobile-app-first platforms offering zero public developer access. The only KG exception is Tunduk (X-Road), which ironically has the most architecturally sophisticated infrastructure in the region.

**Mandatory fiscal APIs represent the highest-impact MCP opportunity.** Webkassa (KZ cash registers), Factura.uz, and DIDOX (UZ e-invoicing) are not optional — every business in these countries must integrate with them. An MCP server for these services immediately serves the entire addressable market. The catch: Kazakhstan's ESF (electronic invoices) and Salyk (tax authority) use SOAP and GOST cryptography, making them **XL builds** that require deep infrastructure investment.

**The "no MCP exists" finding is nearly universal.** Of 40 services investigated, only **Wildberries, Ozon, and HeadHunter** have existing MCP servers — all three are Russian platforms operating across CIS. Zero Central Asia-native services have MCP implementations. This means the **P0 list** (Kaspi, Forte Bank, Payme, Click, Webkassa, Halyk ePay) represents a completely uncontested greenfield where each MCP server would be first-to-market. Forte Bank's S-size build with 5/5 documentation quality makes it the ideal starting point for establishing the team's velocity before tackling the higher-complexity Kaspi and payment integrations.

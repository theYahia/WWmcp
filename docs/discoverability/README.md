# Discoverability — submission materials

This folder contains drafts and command snippets for promoting WWmcp to:

- GitHub topics (60 sec, free)
- Awesome-MCP lists (PR each, ~30 min)
- Glama / mcp.so directories
- Blog posts (Habr, dev.to)
- Hacker News / Reddit / Twitter
- "good first issue" creation via `gh` CLI

Run these manually — none of them are automatable from a Claude session because they require either GitHub repo settings access, npm credentials, an authored account on a third-party platform, or social-media login.

## Files

| File | Purpose |
|---|---|
| [`github-topics.md`](github-topics.md) | List of topics to set on the GitHub repo (Settings → Topics) |
| [`awesome-mcp-pr.md`](awesome-mcp-pr.md) | PR body templates for awesome-mcp-servers lists |
| [`blog-habr-ru.md`](blog-habr-ru.md) | Russian Habr post draft |
| [`blog-devto-en.md`](blog-devto-en.md) | English dev.to post draft |
| [`hn-reddit-twitter.md`](hn-reddit-twitter.md) | Short-form copy for HN / Reddit / Twitter |
| [`good-first-issues.md`](good-first-issues.md) | `gh issue create` commands for 8 starter contributor issues |

## Order of operations

1. **GitHub topics** — instant, sets up SEO foundation. Do this first.
2. **`good-first-issues.md`** — open the issues so a blog reader has a clear "do this next" path.
3. **Blog post** (Habr OR dev.to — pick one for the first wave). Include the GIF demo and link to the good-first-issues.
4. **Awesome-MCP PRs** — submit after the blog post is live; reference it.
5. **HN / Reddit / Twitter** — the day after the blog post lands, while it's fresh.

Don't fire all channels at once — stagger across 3-5 days for sustained momentum.

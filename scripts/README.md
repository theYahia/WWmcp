# scripts/

## catalog.mjs — источник правды о числах

Считает серверы, версии и tools. Числа берутся **живьём**: каждый сервер поднимается через
stdio и отвечает на `listTools()` (`runSmokeTest` из `@theyahia/mcp-core/testing/smoke`).

Статический подсчёт по грепу врёт и использоваться не должен:

| Сервер | Почему греп ошибается |
|---|---|
| `wildberries` | регистрация в цикле `for (const [name, def] of Object.entries(toolDefinitions))` — греп даёт 3 при реальных 30 |
| `huntflow` | свои обёртки `registerStructured` / `registerText` |
| `retailcrm` | набор зависит от `isReadonly()` |
| `aprovodka` | набор зависит от `ONEC_SERVICES` и `ONEC_WRITE_MODE` |

### Запуск

```bash
pnpm build                              # обязательно: скрипт читает servers/*/dist/index.js
node scripts/catalog.mjs                # перегенерировать scripts/catalog.json
node scripts/catalog.mjs --check        # только проверить, exit 1 при дрейфе (для CI)
node scripts/catalog.mjs --write-readme # + вписать числа в README.md / README.ru.md / docs/index.html
```

Серверы пишут свои логи в stderr — для чистого вывода добавь `2>/dev/null`.

### Что считается дрейфом (→ exit 1 при `--check`)

1. `TOOL_COUNT` в коде ≠ то, что вернул `listTools()`;
2. сервер не поднялся;
3. числа в `README.md` / `README.ru.md` / `docs/index.html` разошлись с живыми
   (все формы записи — в таблице ниже);
4. `scripts/catalog.json` устарел.

### Где числа лежат в документации

Числа записаны в разных формах, и патчер знает их все. Форма, которой в таблице нет,
из-под проверки выпадает молча — так salla стояла с «9 tools» при реальных 22, пока
патчер знал только markdown-таблицу и мёртвый `class="tools-num"` (такого класса в
`docs/index.html` нет вообще).

| Файл | Что | Форма |
|---|---|---|
| `README.md`, `README.ru.md` | версия | `\| v3.1.0 \|` |
| `README.md`, `README.ru.md` | tools | `\| 22 tools \|` |
| `docs/index.html` | версия | `<td class="ver">3.1.0</td>` |
| `docs/index.html` | tools, проза EN | `— 22 tools for products`, `8 tools: SMS, …` |
| `docs/index.html` | tools, проза RU | `22 инструмента`, `8 инструментов`, `1 инструмент` |

Русское склонение пересчитывается при замене: `9 инструментов` → `22 инструмента`.

Два подвоха `docs/index.html`, которых нет в markdown:

1. **Имя пакета и числа — на разных строках.** В README всё в одной строке таблицы, а в
   html строка `<tr>` разложена на четыре: ссылка на пакет, `<td class="ver">`, описание с
   числом прозой, ссылка на исходники. Поэтому имя пакета переносится вниз — но только
   внутри `<tr>…</tr>`.
2. **Пример конфига стоит прямо над таблицей.** В `<pre class="cfg">` упомянут
   `@theyahia/wildberries-mcp`; без сброса контекста на `<tr>` первая строка таблицы (2gis)
   получила бы версию wildberries.

Заменяется **первое** вхождение в строке: `34 инструмента в 11 модулях`, `плюс 2
MCP-подсказки`, `(+ 10 Francophone countries) — 8 tools` остаются нетронутыми.

Регулярка имени пакета — `@theyahia/[a-z0-9-]+` без обязательного суффикса `-mcp`:
`@theyahia/aprovodka` его не имеет и раньше не проверялся вовсе.

Чистая часть вынесена в `scripts/doc-numbers.mjs` — её проверяет
`packages/core/tests/doc-numbers.test.ts`, не поднимая 46 серверов. Среди прочего тест
падает, если в ячейке таблицы витрины появилось число инструментов в форме, до которой
патчер не дотягивается (ищется по слову `инструмент` / `tools`, а не по формату числа).

### Не проверяется

Итоговые числа страницы вне таблиц: `46 серверов` в шапке и подвале, `500+ инструментов`,
`39 серверов` / `7 servers` в заголовках разделов, `76 пакетов` у standalone-репозиториев.
Каталог не знает деления на разделы, поэтому эти числа остаются на ручной сверке.

### `--write-readme` правит только свои строки

По умолчанию **выключен**. В каталоге README 114 строк, из которых ~68 — standalone-репо,
которых в монорепе нет; слепая перезапись их удалит. Скрипт трогает строку, только если
пакет из неё реально существует в `servers/`, и меняет в ней лишь версию и число tools —
описания остаются рукописными. Без флага изменения печатаются диффом и никуда не пишутся.

### Env

Креды подставляются заглушками, имена вытаскиваются из `process.env.X` в исходниках
сервера — руками карту вести не надо. Переменные, меняющие **поведение** (`*_READONLY`,
`ONEC_SERVICES`, `ONEC_WRITE_MODE`, `*_SANDBOX`, `PORT`, `MCP_*` и т.п.), намеренно
не выставляются: каталог отражает конфигурацию по умолчанию. `aprovodka` и `retailcrm`
помечаются в выводе как «при настройках по умолчанию».

### catalog.json

Читай его, а не считай заново. Формат:

```jsonc
{
  "generatedAt": "...",
  "servers": 46, "serversConnected": 46, "totalTools": 501,
  "entries": [{
    "dir": "wildberries", "name": "@theyahia/wildberries-mcp", "version": "3.1.0",
    "description": "...", "connected": true, "toolCount": 30, "tools": ["..."],
    "declaredToolCount": 30,      // null, если TOOL_COUNT не объявлен числом
    "envDependent": false,
    "shortDescriptions": [],      // тулы с описанием < 20 символов
    "error": null
  }]
}
```

## Тесты уровня монорепо

Живут в `packages/core/tests/` — это единственное место, чей `test` поднимает
`turbo test` без правки корневых `package.json` / `turbo.json`. Запуск:

```bash
pnpm --filter @theyahia/mcp-core test
```

| Файл | Что проверяет |
|---|---|
| `doc-numbers.test.ts` | `scripts/doc-numbers.mjs` — все формы записи версии и числа инструментов; ни одно число в ячейках `docs/index.html` не осталось вне досягаемости патчера |
| `skills-consistency.test.ts` | имена инструментов в `servers/*/.claude/skills/**/SKILL.md` существуют у своего сервера; `allowed-tools` разрешает хотя бы один `mcp__` |

Обоим нужен свежий `scripts/catalog.json` — сначала `pnpm build && node scripts/catalog.mjs`.

### skills-consistency: как отличается вызов инструмента от поля схемы

Имена инструментов берутся из `catalog.json` (живой `listTools()`), из скиллов вынимаются
токены в обратных кавычках. Токен считается вызовом, если его первый сегмент начинает
хоть какой-то реальный инструмент монорепы — набор префиксов собирается из самого каталога,
рукописного списка глаголов нет. Так сами собой отсеиваются `city_code`, `area_id`,
`moment_from`, `first_name`, `crm_deals`, `approval_flow`: ни `city`, ни `crm`, ни
`approval` ничего не начинают.

Дальше — три явных исключения:

| Что | Почему |
|---|---|
| `*_xxx` (`refund_xxx`, `pay_xxx`) | плейсхолдер в примере вывода, не вызов |
| `*_id`, `*_href` (`customer_id`, `store_href`, `order_id`) | идентификаторы и ссылки в схемах; сталкиваются с существительными-префиксами реальных инструментов (`customer_notes_list`, `store_inventories`, `order_payment_create`) |
| `approve_write`, `rollback_write` у `aprovodka` | инструменты есть, но регистрируются только при `ONEC_WRITE_MODE != off`, а каталог снят с дефолтным окружением |

Слепые углы, принятые сознательно: односегментные токены (`chat`, `search`) не проверяются —
в обратных кавычках такой формы обычно стоят значения полей; и единственный инструмент
монорепы на `_id` (`get_user_by_id`) попадает под правило про идентификаторы.
